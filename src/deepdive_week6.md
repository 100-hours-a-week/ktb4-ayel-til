## 네트워크 모델

네트워크는 **데이터를 송수신하는 기기들 간의 연결을 통해 정보와 자원을 공유할 수 있게 하는 통신 시스템**이다. 하지만 서로 다른 장치와 운영체제, 통신 방식이 존재하기 때문에 데이터 전송 과정을 통일된 기준으로 관리할 필요가 있었다.

이를 위해 네트워크 모델이 등장했다.

네트워크 모델은 데이터가 송수신되는 과정을 계층별로 나누어 정의하여 통신 과정을 체계적으로 관리하고, 서로 다른 시스템 간의 원활한 통신을 가능하게 한다.

네트워크 모델로는 **OSI 7계층 모델**과 **TCP/IP 4계층 모델**이 있다. OSI 7계층 모델은 데이터 통신 과정을 계층별로 구분하여 역할을 정의한 참조 모델이며, TCP/IP 4계층 모델은 현재 인터넷에서 실제로 사용되는 프로토콜을 기반으로 구성된 모델이다.

![](./images/network.png)


---

### OSI 7계층 모델

OSI 7계층 모델은 네트워크 통신 과정을 7개의 계층으로 나누는 **개념적 프레임워크**다. 네트워크 통신은 다양한 하드웨어, 운영체제, 프로토콜이 함께 사용되기 때문에 통신 과정을 표준화할 필요가 있었다. 국제표준화기구는 통신 기능을 계층별로 구분한 OSI(Open Systems Interconnection) 모델을 개발했다.

OSI 모델은 각 계층이 수행해야 할 역할을 정의하여 서로 다른 시스템 간의 통신을 가능하게 하며, 특정 계층의 기능 변경이 다른 계층에 미치는 영향을 최소화할 수 있다.

네트워크 장애가 발생했을 때 계층별로 문제를 분석할 수 있어 **네트워크 문제 진단의 기준**으로 활용된다.

| 계층 | 역할 |
| --- | --- |
| 응용 계층 | 사용자와 직접 상호작용하는 응용 프로그램 및 네트워크 서비스 제공 |
| 표현 계층 | 데이터 형식 변환, 암호화, 압축 등을 수행하여 데이터를 표현 |
| 세션 계층 | 응용 프로그램 간의 통신 세션 생성, 유지 및 종료 |
| 전송 계층 | 데이터 전송을 담당하며 TCP/UDP를 통해 신뢰성 있는 통신을 제공 |
| 네트워크 계층 | IP 주소를 기반으로 데이터의 경로를 결정하고 라우팅 수행 |
| 데이터 링크 계층 | 네트워크 내에서 데이터 전송을 담당하며 프레임 생성, 오류 검출 및 흐름 제어 기능 수행 |
| 물리 계층 | 물리적 매체를 통해 데이터를 비트 단위의 신호로 변환하여 전송 |

데이터는 응용 계층에서 생성되어 물리 계층까지 순차적으로 전달되며, 각 계층은 자신의 역할에 맞는 정보를 헤더에 추가한다.

---

### **TCP/IP 4계층 모델**

TCP/IP 모델은 현재 인터넷에서 실제로 사용되는 네트워크 모델이다.

OSI 7계층 모델이 통신 과정을 개념적으로 설명하기 위한 참조 모델이라면, TCP/IP 모델은 실제 인터넷 통신에 사용되는 프로토콜을 기반으로 구성된 모델이다.

OSI 7계층을 **단순화한 구조**로 네트워크 접근 계층, 인터넷 계층, 전송 계층, 응용 계층의 4개 계층으로 구성된다. 각 계층은 독립적인 역할을 수행하며 데이터를 효율적으로 전달할 수 있도록 설계됐다.

| 계층 | 역할 |
| --- | --- |
| 응용 계층 | 사용자와 직접 상호작용하는 응용 프로그램 및 네트워크 서비스 제공 |
| 전송 계층 | TCP/UDP를 이용하여 데이터 전송 및 신뢰성 있는 통신 제공 |
| 인터넷 계층 | IP 주소를 기반으로 패킷의 경로를 결정하고 목적지까지 전달 |
| 네트워크 접근 계층 | 네트워크를 통해 데이터를 전송하며 프레임 생성 및 물리적 전송 담당 |

데이터는 응용 계층에서 네트워크 접근 계층까지 순차적으로 전달되며, 각 계층은 자신의 역할에 맞는 정보를 헤더에 추가한다.

---

## 데이터 전달 과정

데이터 전달 과정은 **송신자가 생성한 정보가 네트워크를 통해 수신자에게 전달되는 일련의 과정**이다. 네트워크에서 데이터는 한 번에 전송되는 것이 아니라 여러 네트워크 장비를 거치며 목적지까지 이동한다.

예시로, 사용자가 웹 브라우저에서 사이트에 접속하면 요청 데이터가 생성되어 네트워크를 통해 목적지 서버로 전달된다. 서버의 응답 데이터는 다시 사용자에게 전달된다.

이 과정에서 데이터는 스위치와 라우터를 거치며 목적지까지 이동한다.

```objectivec
사용자 → 스위치 → 라우터 → 인터넷 → 서버
```

데이터가 목적지까지 전달되기 위해서는 네트워크 장비가 올바른 경로를 선택해야 하며, 이 과정에서 스위칭과 라우팅이 수행된다.

---

### 라우팅

라우팅은 데이터 패킷이 목적지까지 전달될 수 있도록 최적의 경로를 선택하는 과정이다. 이 과정은 **네트워크 계층**에서 수행되며, 라우터는 IP 주소를 기반으로 목적지 네트워크를 확인하고 적절한 경로를 결정한다.

라우터는 두 개 이상의 네트워크를 연결하는 네트워크 장치로, 서로 다른 네트워크 간의 통신을 가능하게 한다. 데이터가 여러 네트워크를 거쳐 이동하는 경우 라우터는 라우팅 테이블을 참고하여 다음 목적지를 결정하고 패킷을 전달한다. 라우팅 테이블이란 라우터가 목적지 네트워크까지 패킷을 전달하기 위해 참조하는 경로 정보 목록이다.

라우팅은 **경로를 설정하고 관리하는 방식에 따라** 정적 라우팅과 동적 라우팅으로 구분된다.

- **정적 라우팅 (Static Routing)**

  관리자가 목적지까지의 경로를 직접 설정하는 방식이다. 설정이 단순하고 자원 사용량이 적지만, 네트워크 구조가 변경될 경우 수동으로 수정해야 한다.

- **동적 라우팅 (Dynamic Routing)**

  라우터가 라우팅 프로토콜을 이용하여 경로 정보를 자동으로 교환하고 최적의 경로를 계산하는 방식이다. 네트워크 변화에 유연하게 대응할 수 있지만 추가적인 자원을 사용한다.


이를 통해 데이터는 여러 네트워크를 거쳐 목적지까지 전달될 수 있으며, 네트워크 환경에 적합한 경로를 선택하여 효율적인 통신을 제공할 수 있다.

---

### 스위칭

스위칭은 동일한 네트워크 내에서 데이터를 목적지 장치로 전달하는 과정이다. 이 과정은 **데이터 링크 계층**에서 수행되며, 스위치는 MAC 주소를 기반으로 목적지 장치를 식별하여 데이터를 전달한다.

스위치는 네트워크에 연결된 장치들의 MAC 주소를 학습하여 MAC 주소 테이블에 저장한다. 이후 프레임이 수신되면 목적지 MAC 주소를 확인하고 해당 장치가 연결된 포트로만 데이터를 전달한다.

스위칭은 **데이터를 전송하는 방식에 따라** 회선 교환, 패킷 교환, 메시지 교환 방식으로 구분된다.

- **회선 교환 (Circuit Switching)**

  송신자와 수신자 사이에 전용 통신 경로를 먼저 설정한 후 데이터를 전송하는 방식이다. 일정한 대역폭을 보장할 수 있지만, 사용하지 않는 시간에도 회선이 점유된다는 단점이 있다.

- **패킷 교환 (Packet Switching)**

  데이터를 여러 개의 패킷으로 분할하여 전송하는 방식이다. 각 패킷은 독립적으로 전달되며, 수신 측에서 다시 조립된다. 네트워크 자원을 효율적으로 활용할 수 있어 현재 인터넷에서 가장 널리 사용된다.

- **메시지 교환 (Message Switching)**

  데이터를 하나의 메시지 단위로 전송하는 방식이다. 중간 노드가 메시지를 저장한 후 다음 노드로 전달하는 Store-and-Forward 방식을 사용하지만, 전송 지연이 발생할 수 있어 현재는 거의 사용되지 않는다.


이를 통해 데이터는 동일한 네트워크 내의 목적지 장치로 정확하게 전달될 수 있으며, 불필요한 데이터 전송을 줄여 네트워크 효율을 높일 수 있다.

## 헤더

헤더는 데이터 앞부분에 추가되는 정보 영역으로, 데이터 형식이나 주소, 전송 제어 정보 등을 포함한다. 네트워크에서는 출발지 주소, 목적지 주소, 프로토콜 정보 등 데이터 전송에 필요한 정보가 헤더에 저장된다. 이를 통해 네트워크 장비와 수신 시스템은 데이터를 올바르게 전달하고 해석할 수 있다.

네트워크 모델에서 데이터는 각 계층을 거치면서 해당 계층의 역할에 맞는 헤더가 추가된다. 헤더의 종류로는 **Ethernet 헤더, IP 헤더, TCP / UDP 헤더**가 있다.

| 헤더 종류 | 계층 | 주요 정보 | 역할 |
| --- | --- | --- | --- |
| Ethernet 헤더 | 데이터 링크 계층 | MAC 주소, EtherType | 동일한 네트워크 내에서 장치 식별 및 데이터 전달 |
| IP 헤더 | 네트워크 계층 | IP 주소, TTL, Protocol | 목적지까지의 경로 결정 및 패킷 전달 |
| TCP / UDP 헤더 | 전송 계층 | 포트 번호, 순서 번호, 체크섬 | 응용 프로그램 식별 및 데이터 전송 제어 |

---

### Ethernet 헤더

Ethernet 헤더는 **데이터 링크 계층**에서 사용되는 헤더로, Ethernet 프레임의 시작 부분에 위치한다. Ethernet 프레임은 동일한 네트워크 내에서 데이터를 전달하기 위한 기본 데이터 단위이며, 스위치는 Ethernet 헤더에 포함된 정보를 이용하여 데이터를 목적지 장치로 전달한다.

![](./images/ethernet.webp)

Ethernet 헤더의 가장 중요한 정보는 **목적지 MAC 주소**와 **출발지 MAC 주소**다. 스위치는 이 정보를 이용하여 프레임을 적절한 장치로 전달한다.

EtherType 필드는 상위 계층 프로토콜의 종류를 식별하는 역할을 수행한다.

Ethernet 프레임은 Ethernet 헤더, 데이터(Payload), FCS(Frame Check Sequence)로 구성되며, FCS는 전송 과정에서 발생한 오류를 검출하는 데 사용된다.

---

### IP 헤더

IP 헤더는 **네트워크 계층**에서 사용되는 헤더로, IP 패킷의 시작 부분에 위치한다. IP 패킷은 인터넷 프로토콜(IP)을 통해 전달되는 데이터 단위이며, 라우터는 IP 헤더에 포함된 정보를 이용하여 패킷을 목적지까지 전달한다.

![](./images/IP.webp)

IP 헤더의 가장 중요한 정보는 **출발지 IP 주소**와 **목적지 IP 주소**다. 라우터는 목적지 IP 주소를 확인하여 패킷의 전달 경로를 결정한다.

TTL(Time To Live)은 패킷의 무한 순환을 방지하고, Protocol 필드는 상위 계층 프로토콜의 종류를 식별한다.

IP 패킷은 IP 헤더와 데이터(Payload)로 구성되며, 데이터 영역에는 TCP 세그먼트나 UDP 데이터그램과 같은 상위 계층 데이터가 포함된다.

---

### TCP / UDP 헤더

TCP/UDP 헤더는 **전송 계층**에서 사용되는 헤더로, 데이터를 올바른 응용 프로그램에 전달하기 위한 정보를 포함한다. 전송 계층은 종단 간 통신을 담당하며, TCP와 UDP는 대표적인 전송 계층 프로토콜이다.

![](./images/tcp:udp.jpg)

TCP/UDP 헤더의 가장 중요한 정보는 **출발지 포트**와 **목적지 포트**다. 운영체제는 포트 번호를 이용하여 데이터를 처리할 응용 프로그램을 식별한다.

TCP는 순서 번호, 확인 응답 번호, 체크섬 등을 이용하여 신뢰성 있는 통신을 제공한다.

UDP는 헤더 구조가 단순하여 빠른 전송이 가능하지만 데이터 손실이나 순서를 보장하지 않는다.

## 캡슐화와 역캡슐화

캡슐화(Encapsulation)는 데이터를 송신하기 위해 **각 계층이 자신의 프로토콜 헤더를 추가하며 데이터를 감싸는 과정**이다. 응용 계층에서 생성된 데이터는 전송 계층, 네트워크 계층, 데이터 링크 계층을 거치면서 필요한 헤더가 순차적으로 추가되고, 최종적으로 물리 계층을 통해 전송된다.

이 과정은 택배 배송에 비유할 수 있다. 사용자가 보내려는 데이터가 택배 물품이라면, 각 계층의 헤더는 배송에 필요한 송장 정보와 같다. 발신자 주소, 수신자 주소, 배송 방식 등의 정보가 추가되어야 택배가 목적지까지 전달되는 것처럼, 네트워크에서도 각 계층의 헤더 정보가 추가되어야 데이터가 목적지까지 전달될 수 있다.

캡슐화를 통해 각 계층은 자신의 역할에 필요한 정보만 처리할 수 있으며, 계층 간 독립성을 유지하면서 효율적인 데이터 전송이 가능해진다.

반대로 역캡슐화(Decapsulation)는 데이터를 수신할 때 **각 계층이 자신의 프로토콜 헤더를 제거하여 원래 데이터를 복구하는 과정**이다. 수신 측은 데이터 링크 계층부터 전송 계층까지 순차적으로 헤더를 해석하고 제거하며, 최종적으로 응용 계층에 원본 데이터를 전달한다.

## 네트워크 문제 진단

네트워크 문제 진단은 네트워크 통신 과정에서 발생하는 장애의 원인을 파악하고 해결하기 위한 과정이다. 인터넷 연결 불가, 속도 저하, 접속 지연 등 네트워크 오류의 정확한 원인을 하드웨어 고장, 구성 오류, 트래픽 과부하 등에서 찾아내어 해결하는 것을 의미한다.

네트워크 문제가 발생한 위치를 확인하기 위해 다양한 진단 도구를 사용한다.

- **네트워크 구성 확인 (ipconfig)**

ipconfig는 현재 시스템의 네트워크 계층의 설정 정보를 확인하는 명령어이다. IP 주소, 서브넷 마스크, 기본 게이트웨이 등의 정보를 확인하여 네트워크 설정 문제를 점검하는 데 활용된다.

- **연결성 테스트 (ping)**

ping은 목적지와의 네트워크 연결 상태를 확인하는 명령어이다. 패킷이 정상적으로 전달되는지 테스트하는 데 사용되며, IP 계층의 통신 상태를 확인할 수 있다.

- **경로 추적 (tracert)**

tracert는 목적지까지 데이터가 이동하는 경로를 확인하는 명령어이다. 패킷이 거치는 라우터를 추적하여 네트워크 장애나 지연이 발생한 구간을 파악하는 데 사용된다.

IP 계층에서 패킷의 이동 경로를 확인할 수 있다

- **DNS 조회 (nslookup)**

nslookup은 도메인 이름과 IP 주소의 매핑 정보를 조회하는 명령어이다. DNS 서버의 동작 상태를 확인하거나 이름 해석 문제를 진단하는 데 사용된다. 주로 응용 계층의 DNS 서비스 동작 여부를 확인하는 데 활용된다.

- **패킷 분석 (Wireshark)**

Wireshark는 실제 네트워크 패킷을 수집하여 헤더와 통신 과정을 분석하는 도구다. Ethernet 헤더, IP 헤더, TCP/UDP 헤더를 확인하여 네트워크 통신 과정을 분석하는 데 활용된다. 또한, 캡슐화된 패킷의 헤더 정보를 분석하여 통신 오류나 장애 원인을 파악할 수 있다.

## 결론

네트워크 모델은 복잡한 데이터 통신 과정을 계층별로 구분하여 관리하기 위해 등장했으며, 대표적으로 OSI 7계층 모델과 TCP/IP 4계층 모델이 사용된다. 데이터는 응용 계층에서 생성된 후 전송 계층, **인터넷 계층, 네트워크 접근 계층**을 거쳐 물리적인 신호로 전달되며, 이 과정에서 라우팅과 스위칭을 통해 목적지까지 이동한다.

데이터가 계층을 통과하는 동안에는 각 계층의 역할에 맞는 헤더가 추가되는 캡슐화 과정이 수행된다. 전송 계층에서는 TCP/UDP 헤더, 네트워크 계층에서는 IP 헤더, 데이터 링크 계층에서는 Ethernet 헤더가 추가되어 데이터 전달에 필요한 정보를 제공한다.

수신 측에서는 역캡슐화 과정을 통해 헤더를 순차적으로 해석하고 제거하여 원본 데이터를 복구한다.

이러한 계층 구조와 캡슐화 방식은 **네트워크 문제 진단의 기준**이 된다. 관리자는 각 계층의 헤더 정보와 진단 도구를 활용하여 장애 위치와 원인을 파악할 수 있으며, 문제를 단계적으로 분리하여 보다 효율적으로 진단할 수 있다.

따라서 네트워크 모델과 캡슐화 구조를 이해하는 것은 데이터 통신 원리를 이해하는 것뿐만 아니라, **실제 네트워크 환경에서 발생하는 문제를 효과적으로 진단하고 해결하는 데 중요하다.**
