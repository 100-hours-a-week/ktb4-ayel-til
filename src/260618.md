- Network: 데이터를 송수신하는 기기들 간의 연결을 통해 정보와 자원을 공유할 수 있게 하는 통신망 시스템

    - 사용하는 이유: 다양한 사용자와 기기 간에 정보를 공유하고, 하드웨어·소프트웨어 자원을 공동으로 활용하기 위해

- NIC: 컴퓨터, 서버, 또는 기타 네트워크 장치(노드)가 네트워크에 연결되도록 해주는 하드웨어 구성 요소

    - 사용하는 이유: 컴퓨터가 네트워크에 데이터를 송수신하며 통신할 수 있도록 하기 위해

- Mac Address: 네트워크 장치의 NIC에 부여된 물리적 식별자로, 같은 네트워크 안에서 장치를 구분하는 주소

    - 사용하는 이유: 네트워크 내에서 장치를 식별하고, 데이터를 원하는 장치로 전달하기 위해 사용

- Gateway: 서로 다른 네트워크 또는 프로토콜 간의 통신을 가능하게 하는 출입구 역할의 장치 또는 시스템

    - 사용하는 이유: 네트워크 간의 데이터 전송 및 프로토콜 변환을 위해 사용됨

- Router: IP 주소를 기준으로 데이터가 어느 네트워크로 가야하는지 경로를 정하는 장치

    - 사용하는 이유: 네트워크 간 데이터의 효율적인 전달과 인터넷 통신을 가능하게 하기 위해 사용됨

- Switch: 같은 네트워크 안에서 MAC 주소를 보고 데이터를 필요한 장치에게만 전달하는 장비

    - 사용하는 이유: LAN 내부에서 장치 간 통신을 효율적으로 처리하고, 불필요한 데이터 전송을 줄이기 위해

- Inline: 네트워크 상의 데이터 패킷이 반드시 특정 장비를 통과하도록 설계된 네트워크 구조

    - 사용하는 이유: 모든 트래픽을 실시간으로 검사·제어하여 보안 정책 적용, 접근 제어, 트래픽 관리 및 서버 보호를 위해

- Out-of-Path: 실제 트래픽 경로 밖에서 복사된 패킷을 받아 분석하는 네트워크 구조

    - 사용하는 이유: 서비스에 영향을 주지 않으면서 보안 탐지, 성능 모니터링, 네트워크 분석을 수행하기 위해

- Wireshark: 네트워크 인터페이스를 지나는 패킷을 캡처하고 분석할 수 있는 오픈소스 네트워크 프로토콜 분석 도구

    - 사용하는 이유: 네트워크 장애 분석, 패킷 흐름 확인, 프로토콜 동작 검증 및 보안 분석을 위해

- Failover: 주 시스템이나 장비에 장애가 발생했을 때 대기 중인 예비 시스템으로 자동 전환하는 기술

    - 사용하는 이유: 서비스 중단을 최소화하고 시스템의 가용성과 안정성을 높이기 위해

- SPOF (Single Point of Failure): 하나의 구성 요소가 장애를 일으켰을 때 전체 시스템이나 서비스가 중단되는 단일 장애 지점

    - 사용하는 이유: 시스템 설계 시 장애 위험 요소를 파악하고 이중화 및 고가용성 구조를 구축하기 위해

- 네트워크 캡처 (Packet Capture): 네트워크를 통해 송수신되는 패킷을 수집하여 저장하거나 분석하는 과정

    - 사용하는 이유: 통신 과정 확인, 장애 원인 분석, 보안 위협 탐지 및 프로토콜 동작 검증을 위해
