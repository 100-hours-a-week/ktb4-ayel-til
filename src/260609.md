## 동시성과 병렬성
> 동시성은 "동시에 처리하는 것처럼 보이는 것", 병렬성은 "실제로 동시에 실행되는 것"이다.

--- 

### 1. 동시성
> CPU가 작업을 빠르게 전환하여 여러 작업이 동시에 실행되는 것처럼 보이는 기술

### 알아야 하는 이유
동시성은 많은 사용자 요청이 몰리는 백엔드 서버에서 적절히 자원을 관리하고, 
프로그램 유지보수 시 병렬 작업 구조를 이해하고 최적화하기 위해 필요함

### 특징
1. 효율적인 시스템 자원 활용
2. 사용자 경험 개선

### 동작방식
> CPU가 작업을 빠르게 전환하며 실행하는 동작은 스케줄러에 의해 관리

1. 작업 분할: 실행해야 할 작업을 작은 단위로 나눔
2. 시간 할당: 각 작업에 짧은 실행 시간을 할당하여 순차적으로 실행
3. 컨텍스트 스위칭: 작업 간 전환 시 필요한 상태를 저장하고 복원하여 작업이 중단 없이 진행

---

## 2. 병렬성
> 여러 CPU 코어 또는 여러 프로세서를 사용하여 여러 작업을 물리적으로 동시에 실행하는 기술

### 사용이유
- 운영체제 <- 자원을 효율적 사용
- 병렬성 -> 여러 코어를 활용해서 작업을 동시 수행하려고하는 것
  - 시스템의 성능을 극대화

1. 성능 향상: 여러 작업을 동시에 처리하여 실행 시간 단축
2. CPU 활용도 증가: 여러 코어를 모두 활용 가능
3. 실시간 처리의 사용자 경험 개선: 게임, 스트리밍, 영상 처리 등에서 빠른 응답 제공
4. 대규모 데이터 처리 속도 극대화: 머신러닝, 빅데이터 분석 속도 향상

### 특징
1. 실제 동시 실행: 여러 코어에서 동시에 실행
2. 하드웨어 의존: 멀티코어 CPU 필요
3. 작업 독립성: 작업 간 간섭이 적어야 함
4. 계산 중심 작업에 적합: 머신러닝, 영상처리, 시뮬레아션

### 동작 방식
1. 작업 분할
- 실행할 작업을 독립적인 단위로 나눔

2. 코어(자원) 할당
- 분할된 작업을 CPU 코어 할당

3. 병렬 실행
- 각 코어가 병렬로 실행

4. 결과 통합
- 결과를 취합하여 최종결과 통합

5. 오류처리(복구 및 관리)
- 병렬 처리 도중 오류가 발생하면 재시도하거나 문제를 해결하여 작업이 계속 진행되도록 보장함

* 실무에서 게임, 영상 작업, 인공지능 학습 활용

### 팁
1. 병렬성은 항상 정답이 아니다
  - 병렬 <- 빠른 작업 속도
  - 작업 분할, 결과 합치는 비용이 생각보다 비싸다
    - 작업 분할 비용 + 스레드 생성 비용 + 결과 병합 비용 = x
    - 싱글 코어 동시성 = y
    - x < y 명백히 x가 유리할 때만 병렬성을 한다.

2. 공유 자원 조심
- 여러 개의 코어가 병렬
- 동시 사용하는 자원 <- 접근할 때 조심
- Race Condition 문제 발생 할 수 있다
  - Race Condition란 공유 자원을 둘 이상의 스레드 혹은 프로세스가 읽거나 쓰면서 결과값이 의도와 달라질 수 있는 문제

3. 물리적인 제한
- 코어 수를 잘 살펴야한다
- AWS - Core
- 해당 스펙을 조사 해야한다. (CPU 코어 수 조사)

## 스케줄러와 스케줄링
> 스케줄러는 작업의 실행 순서를 "관리"하는 주체이고, 스케줄링은 작업의 실행 순서를 "결정"하는 정책이다.

---

### 1. 스케줄러

> 프로세스나 스레드의 실행 순서를 관리하는 역할

운영체제의 핵심 구성 요소로, CPU와 같은 시스템 자원을 적절히 분배하기 위해 프로세스나 스레드의 실행 순서를 관리하는 역할

### 사용 이유
1. 자원 독점: 무거운 연산 하나가 들어오면 CPU가 이것만 처리한다
2. 기아 상태: 먼저 온 것, 가장 급한 프로세스 먼저 하자 -> "기아 상태"
- 우선 순위가 밀림
3. 시스템 낭비: 
- CPU idle <- 노는 상태
- 디스크 I/O 를 기다리는 상태 ← 연산, disk 저장
  - 구조적으로 CPU는 디스크의 저장 과정을 기다림
  - 이럴 때 다른 작업 처리하면 효율이 올라간다

> 시스템 성능을 최적화하고 사용자 경험을 개선하며, 시스템의 안정성과 공정성을 보장

### 스케줄러의 목표
1. CPU 이용률 최대화
- CPU가 컴퓨터 자원 중 가장 비싼 자원
2. 처리량 최대화
- 단위 시간이 안에 처리할 수 있는 작업의 양을 최대화 하고 싶다
3. 총 처리 시간 감소
- 작업 A, 작업 시작 부터 작업 완료까지 시간을 총 처리 시간
4. 대기 시간을 최소화
5. 응답 시간 최소화


### 스케줄러의 주요 기능
1. 작업 선택
- 실행 가능한 프로세스 또는 스레드 중에서 어떤 작업을 실행할지 결정

2. 자원 분배
- CPU와 같은 제한된 자원을 여러 작업이 공평하게 사용할 수 있도록 분배
- 각 작업에 짧은 시간(타임 슬라이스)을 할당하고 순환적으로 실행

3. 컨텍스트 스위칭 관리
- 작업 간 전환 시, 이전 작업의 상태 PCB에 저장하고,
  새로운 작업의 상태 PCB를 복원하여 작업이 중단 없이 진행되도록 함

### 스케줄러의 종류
1. 장기 스케줄러
- 역할
  - 보조기억장치(디스크,SSD)에 있는 프로그램 중에서 어떤걸 올리는지 그래서 어떻게 실행 프로세스로 만들지
  - 시스템에 얼마나 많은 작업을 실행할지 결정
- 특징 
  - 시스템에 한 번에 많은 프로세스가 올라오지 않도록, 제어 하는
  - 현대 OS에서는 그렇게까지는 많이 사용되지 않음
  - 램이 싸졌다

2. 중기 스케줄러 (스왑 관리자)
- 역할
  - 메모리를 쓰다가 부족하면 활성화된 프로세스 중에서 일부를 중단 시키고 디스크에 스왑 영역을 옮기고 여유 생기면 다시 가져옴
  - 메모리에 있는 작업 중 어떤 작업을 임시로 중단(스왑)할지 결정
- 특징
  - 가상 메모리 사용: 시스템 안정성을 더 높이는 스케줄러

3. 단기 스케줄러 (CPU 스케줄러)
- 메모리의 준비 상태로 있는 프로세스 중에서 CPU를 할당 받을 프로세스를 결정함
- 특징
  - 밀리초 단위 빠르게 동작해서 속도가 상당히 빠르다
  - 가장 자주 실행되는 스케줄러
  - 실행 가능한 작업 중 다음에 CPU를 사용할 작업을 결정

---

## 2. 스케줄링
> CPU 사용할 순서를 결정하는 운영체제의 정책

- CPU와 같은 자원을 프로세스와 스레드들이 사용할 수 있도록 줄을 세우는 과정
- 운영체제는 프로세스의 우선순위, 상태(대기, 실행, 종료), 자원 가용성을 종합적으로 고려하여 스케줄링을 수행함
- 이를 통해 공정성을 확보하고 시스템 성능 최적화를 목표로 설계
- ex) 규칙, 정책을 만들어 놓은걸 스케줄링

### 스케줄링의 목표
1. CPU 이용률 증가: CPU가 놀지 않도록 함 (핵심)
2. 처리량 증가: 더 많은 작업 처리
3. 응답시간 감소: 사용자 요청에 빠르게 반응
4. 대기시간 감소: 프로세스가 기다리는 시간 최소화
5. 공정성 확보: 특정 프로세서 독점 방지 (핵심)

> 시스템 자원을 효율적으로 분배하고 성능과 안정성을 최적화하기 위해서

### 스케줄링의 레벨
1. 고수준 스케줄링
- 메모리에 올릴 프로세스 결정
- 장기적이고 시스템 전체 부하 관리

2. 중간 스케줄링
- 메모리 부족할 때 일부 프로세스를 잠시 내보내는 역할
- 목표: 
  - 메모리 확보
  - 시스템의 안정성 유지

3. 저수준 스케줄링
- CPU를 사용할 프로세스 결정
- 스케줄링 <- 보통 여기를 얘기함
- 실행 빈도가 상당히 짧고 많이 실행된다

### 사용 방법

#### 스케줄링 정책 설정
1. 서버 환경: 가성비
2. 실시간 시스템: 실시간이 올라가면 비쌈
3. 데스크톱 환경

#### 스케줄링 알고리즘
1. FCFS (First Come First Served)
- 먼저 온 작업 먼저 처리
- 장점: 구현 쉬움
- 단점: 먼저 온 프로세스 작업 시간이 길면 전체가 기다림 -> Convoy Effect

2. SJF (Shortest Job First)
- 가장 짧은 작업 먼저 처리
- 장점: 
  - "평균" 대기시간 제일 적다
  - 운영체제에서 가장 효율적이다
- 단점:
  - 프로세스가 실행될 시간을 예측하기가 힘들다
  - 긴 작업이 굶어 죽는 -> 기아 현상

3. SRTF (Shortest Remaining Time First)
- 남은 실행 시간이 가장 짧은 프로세스를 우선 실행
- SJF의 선점형 버전

- 특징
  - 응답성이 좋아진다
  - 컨텍스트 스위칭 비용이 높아진다
  - 실행 중에도 더 짧은 작업이 들어오면 CPU를 빼앗길 수 있음
  
4. Priority Scheduling
- 우선 순위높은 프로세스 실행
- 장점: 중요한 작업이 항상 빨리 끝나는 작업이 아닐 수 있다
- 단점 : 낮은 우선순위 프로세스가 기아 상태에 빠질 수 있다

5. Round Robin
- 모든 프로세스에게 동일한 CPU 시간(Time Slice) 제공

- 장점
  - 공정성 확보
  - 응답성 우수
- 단점
  - Time Slice 설정이 중요 
    - 너무 작으면 컨텍스트 스위칭 증가 
    - 너무 크면 응답성 저하

#### 선점형과 비선점형 선택
- CPU 강제로 뺏을 수 있냐 없냐의 차이

##### 선점형
- 운영체제 CPU 의 자원 강제 회수해 다른 프로세스에 할당 가능
- Linux, Window, Mac
- 운영체제는 작업을 동시에 실행해야한다
- 비선점형이면, 프로세스가 정상 종료 안되면, 자원 대기를 무한히 한다
  
##### 비선점형
- 프로세스가 스스로 자원을 해제하기 전까지 다른 프로세스가 자원을 강제 회수 불가능
- FCFS, SJF

#### 멀티레벨 큐 스케줄링 (Multilevel Queue)
- 프로세스를 그룹으로 나누고 각 그룹에 맞는 정책(알고리즘)을 적용하는 멀티레벨 큐 스케줄링이 효과적

##### 현대 운영체제에선 다 섞어쓴다
- Linux: 우선 순위 + 라운드로빈 + Fair 스케줄링 + 로드밸런싱
- 윈도우: 동적 우선순위 + 라운드로빈

#### 협업에서 개발가 어떻게 사용하는지?
##### 백엔드 개발자
- 사용하지 않고, 운영체제에서 결정되어 있음 (ex. 스프링 부트, 패스트 API, node.js)
- 성능 최적화 - 트러블 슈팅 <- 이때 사용함
- CPU가 동시처리 할 수 있는 양은 충분한데 사용량은 100%가 아니다.
- 처리 속도가 안 나온다
  - 컨텍스트 스위칭만 엄청나게 하고 있거나 스레드 수가 너무 과다하거나

##### 인프라 엔지니어
- 일부 선택할 수 있다
- Linux
  - 우선 순위 조정
    - nice, renice < 조정
  - CPU Affinity
    - 특정 프로세스 를 특정 CPU
  - 쿠버네티스
    - CPU 할당 정책을 설정
