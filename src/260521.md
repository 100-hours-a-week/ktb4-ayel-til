# 상태(State)

## Stateful
비유: 카페 직원 (“기억해줄게”)

### 장점
- 맞춤형 서비스 제공 가능
- 복잡한 흐름 제어 가능
- 게임, 채팅 등에 사용

### 단점
- 서버가 상태를 계속 저장해야 함
- 사용자가 많아질수록 부담 증가
- 분산 시스템에서 처리 어려움

---

## Stateless
비유: 키오스크 (“누구세요?”)

### 장점
- 서버 부담이 적음
- 확장성이 높음
- 처리 속도가 빠름

### 단점
- 요청마다 많은 정보 전달 필요
- 사용자별 맞춤 서비스 어려움
- 순서가 중요한 작업 처리 어려움

---

# 연결(Connection)

## Connection Oriented
비유: 전화

### 특징
- 실시간 통신에 적합
- 연결 유지 필요
- 데이터 순서 보장
- 신뢰성이 높음

---

## Connectionless
비유: 문자

### 특징
- 빠른 전송 가능
- 연결 과정이 없음
- 데이터 손실 가능
- 순서 보장이 어려움

---

## HTTP는 왜 Stateless, Connectionless일까?

### Stateless인 이유
- 서버가 사용자 상태를 저장하지 않아도 되므로 확장성이 높음
- 여러 서버가 동시에 요청을 처리하기 쉬움

### Connectionless인 이유
- 지속적으로 연결을 유지하지 않아 서버 자원을 효율적으로 사용 가능
- 동시에 많은 사용자를 처리할 수 있음

---

## 인증
“내가 누구인지 확인하는 과정”

사용자의 신원을 확인하는 보안 절차

### 사용 이유
- 사용자 신원을 확인해 시스템 보안을 강화하기 위해

---

## 인가
“이 기능을 사용할 권한이 있는지 확인하는 과정”

인증된 사용자에게 특정 자원에 대한 접근 권한을 부여하는 절차

### 사용 이유
- 사용자별 접근 범위를 제한하기 위해

---

## 쿠키
- 사용자 브라우저에 저장되는 작은 데이터 파일

### 사용 이유
- 웹 사이트의 방문 정보를 기억해 개인화된 서비스를 제공하기 위해서

### 저장되는 정보
- 방문 기록
- 장바구니 정보
- 언어 설정
- 자동 로그인 정보

### 특징
- 브라우저에 저장됨
- 보안성이 상대적으로 낮음

### 사용 방법
- 브라우저에 텍스트 형태로 저장
- 필요 시 서버가 다시 읽어서 사용

---

## 세션(Session)
- 사용자와 서버 간의 연결 상태를 유지하는 기술

### 사용 이유
- 사용자 정보를 서버에서 관리해 보안을 강화하기 위해
- 사용자 맞춤 서비스를 제공하기 위해

### 특징
- 서버에 정보 저장
- 세션 ID 사용
- 쿠키보다 보안성이 높음

### 사용 방법
- 서버가 세션 ID 생성
- 사용자 정보를 서버에 저장
- 브라우저는 세션 ID를 이용해 서버와 통신

## API
- 두 프로그램 사이의 소통을 위한 접점

### 사용이유 
- 서로 다른 시스템이나 애플리케이션 간에 데이터를 교환하고 기능을 공유하기 위해서

### 사용방법
- 개발자가 API 문서를 참고하여 미리 정의된 명령어나 프로토콜을 활용해 
특정 기능을 실행하거나 데이터를 교환할 수 있음

---

## 페이징
- 데이터를 한 번에 처리할 수 있는 적당한 크기(페이지)로 나눠서 페이지 단위로 처리하는 것

### 사용이유
- 데이터를 조금씩 나눠서 보여주고 클라이언트, 서버 부하를 줄이기 위해서

### 표현 방식
- page-based 방식
- 인피니티 스크롤 : 많이 씀

### 구현방식
- offset based : 건너뛰기 방식, 많아지면 느림
  - 장점
    - 구현이 간단하다
  - 단점
    - 데이터가 많으면 느려진다
    - 데이터 변화가 많으면 중복이 생긴다
- key-based : 데이터의 키 값 기준으로 데이터 가져옴
  - 장점
    - 큰 데이터에서도 조회 속도가 빠르다
    - 데이터 추가/삭제 되어도 안정적
  - 단점
    - 특정 구간으로 바로 이동하기 힘들다
    - 순차 탐색만 가능
    - key로 등록해야만 정렬 가능
- cursor-based 
  - 현재 위치를 기준으로 다음 데이터를 조회하는 방식
- token-based
  - 매번 값을 직렬화해서 전달하는 대신, 
  서버에 마지막으로 본 위치 값을 저장해두고 토큰으로 관리하는 방식
