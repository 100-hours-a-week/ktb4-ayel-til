## 1. Inline 네트워크 구조
> 네트워크 상의 데이터 패킷이 반드시 해당 장치를 통과하도록 설계된 네트워크 구조

### 네트워크 장비는 "어디에 놓이느냐"
- 네트워크 기초 개념 + 네트워크 장비
- 네트워크 장비를 이해할 때는, 장비의 기능 충분히 필요하지만,
  - 트래픽 흐름상 이 장비가 어디에 놓이는지도 중요함
- 보안장비는 사용자의 요청이 서버로 가는 길목에 있고
  - 모든 요청이 항상, 반드시 이 장비를 지나는개 Inline 방식
- 네트워크 상 트래픽이 지나는 경로 위에 장비를 배치해서
  - 요청과 응답이 항상 반드시 그 장비를 거치도록 만드는 구조를 인라인
- 인라인 방식 "네트워크의 검문소" 역할

### 특징
1. 반드시 지나간다
- 인라인 구조는 강제성
- 트래픽이 인라인 장비를 우회하지 못하고, 반드시 거쳐야만 도달하는 구조
- 사용자 -> 인라인 장비 -> 서버

2. 트래픽을 직접 제어한다
- 인라인 장비는 트래픽을 검사하고 정책에 따라 처리
  - 요청 허용 또는 차단
  - IP 및 포트 제어
  - 악성 패턴 탐지
  
3. 보안 및 관리 중심 설계

- 이 결과에 따라서 트래픽을 통과시킬지, 아니면 드롭할지, 아니면 다른 곳으로 보낼지 직접 제어할 수 있다

**처리방식**
- 허용: 정상 트래픽을 통과시킴
- 차단: 위험하거나 정책에 맞지 않는 트래픽을 버림
- 필터링: 특정 조건에 따라 트래픽을 제한하거나 조정
- 수정: 필요하면 헤더나 요청 정보를 변경
- 기록: 트래픽 로그를 남김

### 사용 이유
1. 실시간으로 보안 적용
- 인라인 장비 자체가 보안 적용하기 좋다

2. 트래픽 제어 및 관리
- IP 기반 차단
- 포트 기반 제어
- 프로토콜 제어 
- Rate Limit
- 접근 제어

3. 서버 보호
- 인라인 장비가 서버 앞에 있으면 모든 요청을 서버가 처리하지 않아도 된다
- 이런 구조가 백엔드 서버 보호할 때 유용하다
  - Reverse Proxy

4. 성능 최적화
- 커널 모드에서 데이터를 처리하여 빠른 응답 속도와 낮은 네트워크 지연을 보장

5. 인반적인 사용 사례
- 다양한 네트워크 환경에서 보안과 관리 목적을 위해 Inline 구조 활용

### 대표적인 인라인 장비
1. 방화벽
- 대표적인 인라인 장비
- 보안을 위해서 항상 모든 트래픽이 거치도록 설계
- IPS, WAF, IDS 보안 장치 <- 차이점

2. 로드밸런서
- 로드밸런서는 돌아오는 요청을 서버등에게 분비해주는 방식
- Client -> Load Balance -> WAS A/B/C

3. 공유기
- 네트워크 트래픽을 경유하며, 기본적인 데이터 흐름 관리 수행

4. 네트워크 스위치
- 내부 네트워크의 트래픽을 특정 조건에 따라 라우팅
5. 침입 방지 시스템

### 동작 방식
1. 데이터 패킷 통과 및 캡처
2. 실시간 검사 및 규칙 적용
3. 보안 및 성능 최적화
4. 모니터링 및 로그 기록
5. 동작 과정 요약

### 장단점
#### 장점
1. 강제성
2. 실시간 차단
3. 정책 적용 확실함
4. 로그 정보
5. 트래픽 제어
6. 서버보호

#### 단점
1. 병목 현상

2. 단일 장애지점 (SPOF)
- 인라인 장비가 죽으면 전체 서비스가 죽음

3. 잘못된 정책이면 위험하다
- 실제로 트래픽 차단
- 규칙을 잘못만든다
- 모든 서비스가 무조건 죽는다

#### 장애 극복하는 법
1. 이중화
2. Failover
3. Bypass Mode
4. 로드밸런싱
5. 정책 테스트
6. 모니터링
7. 규칙 최적화

### 헷갈리기 쉬운 것들
1. Inline 방식 장비는 이름이 아니라, 장비를 배치하는 방식이다
- 같은 방화벽이라고 해도 트래픽이 무조건 통과하면 Inline

2. Inline이라고 무조건 좋은건 아니다
- 병목이랑 장애 가능성이 높다

💡정리
- 정체: 트래픽이 반드시 특정 장비를 지나가도록 배치하는 방식
- 핵심 특징: 강제 통과 
- 주요 목적: 보안, 트래픽 제어, 성능 관리 
- 대표 장비: 방화벽, IPS, WAF, 로드밸런서, 프록시 
- 장점: 실시간 차단과 강력한 정책 적용 
- 한계: 병목현상, 단일 장애점, 설정 실수 영향

## 2. Out of Path
> 실제 트래픽 경로 밖에서 트래픽 복사본을 받아 분석하는 방식

### 사용 이유
1. 서비스 트래픽에 영향을 주지 않는다
- 분석 장치 고장나더라도 실제 처리 흐름에는 영향을 주지 않는다

2. 모니터링 안정적
- 트래픽을 직접 건들지 않고, 복사본 보니까 모니터링 해도 안정적으로 할 수 있다

3. 탐지와 분석 검증
- 장비들에도 단일책임 원칙 같이 장비에서 하고 싶은 일이 별도로 정해져 있는 경우가 많다

4. 유연한 확장성
- 네트워크 성능 요구에 따라 분석 장치를 추가하거나 독립적으로 배치할 수 있어, 다양한 규모와 환경에서 유연하게 적용 가능

### 특징
1. 경로 외부 동작
2. 비간섭성
3. 탐지 및 분석 중심
4. 서비스 안정성
5. 확장성
6. 직접 차단 한계

### 동작 방식
1. 트래픽 복사 및 수집
2. 실시간 데이터 분석
3. 대응 및 조치
4. 로그 저장 및 모니터링

💡 정리
- 정체: 실제 트래픽 경로 밖에서 복사본을 분석하는 방식
- 핵심 특징: 비간섭, 관찰, 탐지 중심 
- 주요 목적: 보안 탐지, 네트워크 분석, 성능 모니터링 
- 구성 요소: Port Mirroring, TAP, Sensor, SIEM 
- 장점: 서비스 영향이 적고 분석에 유리 
- 한계: 직접 차단이 어렵고 대응은 별도 연동 필요 
- Inline과 차이: Inline은 막는 구조, Out-of-Path는 보는 구조

---

### 인라인 vs Out of Path

| 구분 | Inline | Out-of-Path |
| --- | --- | --- |
| 위치 | 실제 트래픽 경로 위 | 실제 트래픽 경로 밖 |
| 원본 트래픽 처리 | 직접 통과시킴 | 복사본을 분석 |
| 차단 능력 | 직접 차단 가능 | 직접 차단은 제한적 |
| 서비스 영향 | 장비 장애 시 서비스 영향 큼 | Sensor 장애 시 서비스 영향 작음 |
| 주요 목적 | 제어, 차단, 필터링 | 탐지, 분석, 모니터링 |
| 대표 장비 | 방화벽, IPS, WAF, 로드밸런서 | IDS, SIEM, Zeek, Wireshark, Flow Logs |
| 비유 | 도로 위 검문소 | 도로 옆 CCTV |

## 3. WireShark
> 네트워크의 문제, 분석, 소프트웨어 및 통신 프로토콜 개발, 교육에 쓰이는 오픈 소스 패킷 분석 프로그램

### 네트워크 통신은 눈에 안보인다
- 브라우저 접속 중 내부적으로 상당히 많은 일들이 일어난다
- 브라우저 접속 -> DNS 조회 -> TCP 연결 -> TLS Handshake -> HTTP 요청 -> 서버 응답
- 보이지 않는 네트워크의 흐름, 눈으로 볼 수 있게히는 도구
> 내 컴퓨터나 네트워크 인터페이스를 지나가는 패킷을 캡처하고 분석하는 네트워크 프로토콜 분석 도구

### 사용 이유
1. 세밀한 분석
2. 프로토콜 지원
3. 실시간 분석과 후처리

### 와이어샤크로 실제 볼 수 있는 것들
1. DNS 조회: 도메인이 어떤 IP로 해석되는지 
2. TCP 연결: 3-way handshake가 성공하는지 
3. 재전송: 네트워크 손실로 재전송이 발생하는지 
4. TLS Handshake: HTTPS 연결이 어디서 실패하는지 
5. HTTP 요청: 평문 HTTP 요청/응답 내용 
6. 포트 통신: 특정 포트로 패킷이 실제로 나가는지 
7. 응답 지연: 요청 후 응답까지 시간이 얼마나 걸리는지

### 네트워크 계층 구조
1. Frame: 캡처된 프레임 전체 
2. Ethernet II: L2, MAC 주소 
3. Internet Protocol: L3, IP 주소 
4. TCP/UDP: L4, 포트 번호 
5. HTTP/DNS/TLS: L7, 애플리케이션 프로토콜

### 와이어 샤크 사용법
#### 필터
- 모든 네트워크 패킷을 다 보려고하면 힘들다
- 필터를 통해서 내가 보고 싶은 패킷만 골라보는 기능

#### Capture Filter
- 패킷을 캡처하기 전에 적용되는 필터
- 어떤 패킷을 저장할지 결정

#### Display Filter
- 캡처한 다음에 어떤 걸 보여줄지 정하는 필터
- 캡처한 것들 중에서 어떤 패킷을 보여줄지 결정
- 디스플레이 필터를 잘 못 걸어도, 나중에 수정해서 캡처된것들 볼 수 있다
