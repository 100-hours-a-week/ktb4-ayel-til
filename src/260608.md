## 1. 운영체제

> 하드웨어와 소프트웨어를 관리하며, 사용자와 컴퓨터 간 상호작용을 가능하게 하는 시스템 소프트웨어
- Disk, CPU, SSD, 데이터버스 등 사용자가 직접 제어하는건 어렵다
    - 운영체제가 관리해줌으로 해결

### 사용이유
1. 자원 관리 : 운영체제는 CPU, 메모리, 디스크 등의 하드웨어 자원을 효율적으로 분배하고 관리하여 
여러 응용 프로그램이 충돌 없이 원활히 실행될 수 있도록 도움

2. 사용자 편의성 : 복잡한 하드웨어의 동작 방식을 추상화하여 사용자가 명령어 또는 그래픽 기반 인터페이스를 통해 
쉽게 시스템을 사용할 수 있는 환경을 제공

3. 작업 조율 및 멀티태스킹 : 여러 작업을 동시에 실행하거나 조율하여 작업 간의 간섭을 방지하고 
시스템의 생산성을 높이는 동시에 사용자 경험을 극대화

4. 보안 및 안정성 : 운영체제는 데이터와 시스템을 보호하기 위한 보안 메커니즘을 제공하며, 
오류가 발생했을 때 복구 절차를 통해 안정적인 시스템 운영을 보장

---

### 주요계층
1. 사용자 인터페이스: 사용자가 명령을 내릴 수 있도록 하는 창구
2. 시스템 콜: 핵심 서비스들 안전하게 접근할 수 있도록 하는 표준 인터페이스
3. 커널: 하드웨어 자원 관리
- 유저 모드, 커널 모드

## 2. 리눅스
일부 무료로 사용할 수 있는 오픈소스 운영체제

#### 왜 서버엔지니어, 클라우드 엔지니어는 왜 리눅스를 사용하는가?
1. 오픈소스, 생태계
- 핵심 소스 전 세계 오픈되어 있어, 누구나 무료로 다운로드 사용
- 기업의 내부 요구사항에 맞게 뜯어서 사용할 수 있다
   
2. 안정성이 높고 가벼움
- 서버 환경은 상대적으로 비싸다 
- GUI <- 사용자가 편하지만 자원을 많이 씀
- CLI <- 사용자가 불편하지만 자원을 적게 안 씀

3. CLI가 제어가 상당히 강력하다.
- GUI <- 컨트롤 마우스, 키보드
- CLI <- 키보드로만 입력

## 3. 유저 모드, 커널 모드

> 운영체제에서 프로세스 실행 환경을 구분하는 두 가지 실행 모드

### 이유
- 프로그램 < 작은 버그가 있어도 오류가 발생할 수 있다
  - 하드웨어 접근하면? 문제가 생긴다.
- 일반 프로그램은 위험할 수 있도 있으니 중요한 하드웨어 작업은 운영체제 에서만 할 수 있도록 "권한을 분리"

---

### 1. 유저 모드
- 우리가 직접 사용하는 프로그램이 실행 되는 공간 (ex. 줌, 브라우저)
- 제한된 권한만 가지며, 운영 체제와 하드웨어 자원에 직접 접근 못함
- 응용 프로그램의 안정성을 보장하기 위해 격리된 환경에서 실행되며, 사용자 요청은 시스템 호출을 통해 커널에게 위임됨

### 특징
- 제한된 권한: 응용 프로그램은 시스템 호출(System Call)을 통해서만 커널 기능을 사용할 수 있음
- 안정성: 응용 프로그램의 오류가 시스템 전체에 영향을 미치지 않도록 격리된 환경에서 실행
- 상위 계층 작업: 사용자 인터페이스 및 데이터 요청 생성과 같은 상위 작업을 처리

* 사용자 응용 프로그램의 실행을 제한된 권한으로 격리하여 시스템 안정성과 보안을 유지하기 위해서 사용한다.

---

### 2. 커널 모드
- 운영체제의 핵심 기능들이 동작하는 공간 (ex. 파일 열기, 메모리 쓰기, 네트워크 전송, DISK IO)
- 하드웨어 및 시스템 자원에 대한 완전한 접근 권한을 가지며, I/O 제어, 자원 관리, 접근 통제와 같은 핵심 작업을 수행함

### 특징
- 전체 권한: 메모리 관리, CPU 스케줄링, 파일 시스템, 네트워크 통신 등 모든 시스템 자원에 접근 가능.
- 효율성: 사용자 요청을 처리하고 하드웨어 자원을 최적화하여 응용 프로그램과 상호작용.
- 안정성: 사용자 요청은 시스템 호출(System Call)을 통해 Kernel mode에서 처리되어 시스템 보호.
- 하위 계층 작업: 하드웨어와의 직접적인 상호작용(예: 디스크 I/O, 네트워크 제어)을 처리

* 시스템 자원과 하드웨어를 직접 제어하여 효율적이고 안전한 운영을 보장하기 위해서 사용함

---

- 유저 모드에서는 하드웨어에 접근이 제한
- 커널 모드에 접근이 허용
- 유저모드에서 무언가 하드웨어 자원을 사용한다.
- 커널한테 항상 부탁해야한다. 시스템 콜

### 사용이유
1. 안정성 보장: User Mode에서 발생하는 오류가 Kernel Mode로 전파되지 않도록 격리하여 시스템 전체의 안정성을 유지함
2. 보안 강화: 시스템 자원은 Kernel Mode에서만 접근 가능하도록 제한되어, 악성 코드나 비인가 접근으로부터 시스템 자원을 보호
3. 효율적인 작업 분리: 응용 프로그램은 User Mode에서 실행되고, 시스템 자원 제어나 하드웨어 작업은 Kernel Mode에서 처리하여 역할을 분리

---

### 시스템 콜
유저모드에 프로그램 -> 운영체제의 커널 기능을 요청하는 공식 통로 (인터페이스)

* 동작방식: 유저모드 → 시스템 콜 → 커널 모드 → 결과 반환 → 유저 모드

## 4. 메모리 구조
메모리 구조는 프로그램이 빠르고, 안정적으로 실행될 수 있도록 컴퓨터의 메모리를 용도에 맞게 4가지 구역으로 나누어서 관리하는 방식

### 사용이유

1. 프로그램 실행 환경 제공
2. 데이터와 명령어의 분리
3. 프로그램 간 충돌 방지
4. 성능 향상
5. 변화하는 데이터 처리 지원

* 프로그램이 안정적으로 실행되고 데이터를 체계적으로 저장, 관리, 처리할 수 있도록 하기 위해서 사용한다

---

1. 코드(Code)
- 프로그램의 실제 명령어가 저장되는 공간, 읽기 전용(실행 중 코드가 변경되는 것 방지)
2. 데이터(Data)
- 프로그램이 시작될 때부터 끝날 때까지 유지되는 데이터의 공간, 프로그램 실행과 동시에 할당되고, 종료 시 소멸
3. 힙(Heap)
- 필요할 때마다 동적으로 빌려 쓰고 반납하는 자유 공간, 런타임에 크기가 결정
4. 스택(Stack)
- 잠깐 사용하고 버릴 임시 데이터가 쌓이는 작업 공간, 함수가 끝나면 자동 삭제


### 4가지로 나눈 이유
1. 안정성 확보
2. 자원 관리
3. 유연성 제공

---

## 5. 메모리 관리자
시스템 메모리를 관리하여 프로세스 간 자원 할당과 데이터 흐름을 최적화하는 소프트웨어 컴포넌트

### 이유
1. 효율적 자원 활용: 제한된 RAM 용량을 최대한 활용하여 다중 프로세스를 처리 가능.
2. 안정성 보장: 프로세스(데이터) 충돌 방지 및 메모리 보호를 통해 안정적인 시스템 운영 가능.
3. 성능 최적화: 물리적인 메모리의 한계 극복, 필요한 데이터를 적시에 CPU에 전달하여 연산 속도와 성능을 향상.

---

## 6. 메모리 주소 체계
메모리를 아주 작은 공간 나누고, 데이터 저장 및 접근을 위한 고유 주소 체계

### 동작하는 방식
- 운영체제 관리하는데 운영체제는 하드웨어 RAM 에 애플리케이션 (브라우저) 이 접근 못하게 차단
- 애플리케이션은 메모리에 접근 해야하고, 할당해야함

### 1. 논리 주소 (상대 주소)
프로그램이 바라보는 메모리 주소 (실제 메모리 주소 X)

### 2. 물리 주소(절대 주소)
실제 메모리에 주소

### 3. MMU (메모리 관리 장치, 주소 변환)
- CPU: 메모장 프로그램에서 10번 주소에 잇는걸 가져와 명령
- MMU : "메모장" 프로그램이 할당되어 있는 주소 중에서 가상 주소 10번 에 해당하는 물리주소를 변환
  - 물리주소에 있는 L데이터를 가져온다

---

## 7. 메모리 관리 기법 (오버레이와 스왑)
제한된 메모리 환경에서 프로그램 필요한 부분만 메모리에 로드하여 실행하는 기법

### 오버레이 기법
- 하나의 메모리 공간에 프로그램 실행을 위해서 개발자가 직접 코드를 모듈로 쪼개고 필요한 모듈만 올려서 사용하는 방식
- 메모리가 적을 때 사용하는 기법
- 제한된 물리적 메모리에서 큰 프로그램을 실행하기 위해 사용함

### 메모리 스왑
- 메모리가 부족 시 데이터를 디스크(보조기억장치)로 이동하여 RAM 메모리를 확보하고, 필요할 때 다시 메모리로 복구하는 기법
- 물리적 메모리가 부족한 상황에서도 시스템의 안정성과 연속성을 유지하기 위해서 사용함
- 시스템적으로 쿠버네티스, 도커 환경에서는 스왑 사용이 안된다.

---

## 8. 메모리 분할
- 컴퓨터 시스템에서 실행 중인 여러 프로세스가 물리적 메모리를 효율적으로 사용할 수 있도록 메모리를 고정 크기 또는 가변 크기의 블록으로 나누는 기법
- 메모리 자원의 효율적 활용과 프로세스 실행의 안정성을 보장하기 위해 필수적으로 사용

---

### 1. 고정 분할 방식
고정된 크기의 블록으로 미리 나누고, 각 블록에 프로세스를 할당하는 방식

- 장점
  - 관리가 상당히 쉽다.
  - 프로세스 할당 속도가 빠르다.
  - 프로세스 들끼리 충돌 가능성이 낮다.
  
- 단점
  - 내부 단편화: 할당된 메모리 블록 보다, 프로세스가 필요한 공간이 작아서 블록 안에 버려지는 빈 메모리 공간
  - 임베디드 시스템에서 많이 사용한다

---

### 2. 가변 분할 방식
프로세스의 실제 크기에 딱 맞춰 메모리를 동적으로 할당하는 방식

- 장점 
  - 메모리 효율적
- 단점
  - 외부 단편화: 연속된 공간 X
    - 페이징 ← 이라는 방식을 사용한다

---

### 3.  페이징 방식
메모리와 프로그램 둘 다 고정된 크기의 조각 (페이지, 프레임) 으로 짤라서 흩뿌려서 저장

- 장점
  - 메모리를 연속적으로 비워둘 필요가 없다.
- 단점
  - 페이지 테이블을 사용하기 위해서 메모리를 추가로 사용
  - 주소 변환을 할 때 시간이 걸린다.

---

### 4. 세그멘테이션 방식
세그멘테이션은 프로그램의 논리적인 의미 단위로 잘라서 연속된 공간에 보관한다.
 
- 장점
  - 프로그램의 구조를 그대로 반영
  - 데이터를 보호가 공유하기 편하다.
  
- 단점은
  - 세그먼트가 크기가 제각각 -> 외부 단편화가 발생할 가능성이 생긴다
  
- 컴파일러 - 링커

---

### 5. 현대 OS 방식: 페이징-세그멘테이션을 혼합
  - 프로그램을 세그먼트 방식으로 먼저 나눈다.
    - 가변적인 크기 논리적인 단위만큼 잘라서 보관하기에 외부 단편화가 발생할 수 있다.
    - 다시 페이징으로 나눈다.
  - 세그먼트 방식의 장점 + 페이징 방식의 장점
  - 리눅스 버전별로 아니면 배포판 별로 전략이 조금씩 다름

---

## 9. 가상메모리
- 실제 메모리 크기와 관계없이 프로그램이 연속된 주소 공간을 사용할 수 있도록 운영체제가 물리적 메모리를 추상화한 기술
- 물리적인 RAM 보다 큰 프로그램을 실행하면서 + 동시에 여러개의 프로세스를 안전하게 실행하려고 함

### 사용이유
1. 물리적 메모리의 한계 극복
2. 프로세스 간 독립성 제공 (메모리 격리)
3. 메모리 관리 효율성
4. 유연한 프로세스 실행

### 가상 메모리의 구현
- 페이징 기법, 세그멘테이션, 스왑 기법

## 10. 프로세스와 스레드

### 프로세스
> 실행 중인 프로그램의 하나의 흐름
> 운영체제한테 자원을 할당 받아서, 독립적으로 실행되는 단위

### 스레드
> 프로세스 내에서 병렬 처리를 위해서 생성되는 실행 흐름의 최소 단위

### 왜 알아야 하나?
- 웹 애플리케이션의 성능 최적화, 동시성 관리, 그리고 자원 사용을 효과적으로 처리하기 위해서

## 11. IPC
- 기본적으로 프로세스는 독립적인 메모리 공간을 가짐
  - 다른 프로새스랑은 메모리 공간을 공유하지 않는다
- 두 개 이상의 프로세스가 데이터를 교환하고 상호작용하기 위해 사용하는 프로토콜

### 사용이유
- 시스템의 안전성과 효율성을 보장하기 위해 사용함

### 주요 방식
- 운영체제 관리하는 공통의, 프로세스 간의 통신

1. 메세지 전달
- 운영체제 커널을 통해 메시지를 서로 주고 받는 방식
- 직접적인 메모리 공유 없이 안전하게 통신

2. 공유 메모리
- 프로세스들이 서로 공유할 수 있는 메모리 공간을 만드는 방식
- 동시성 접근, 동기화를 해야한다
- 접근하는 프로세스가 많은 경우에는 동기화 문제가 자주 일어 날 수 있다.

## 12. 프로세스 제어 블록(PCB, Process Control Block)
- 운영체제가 개별 프로세스를 관리하기 위해 사용하는 (운영체제 커널의) 데이터 구조

### 알아야 하는 이유
- 멀티태스킹 및 스케줄링 이해
- CPU는 기억하지 않는다
- 프로세스 전환 = 컨텍스트 스위칭
- 스케줄링 등 운영체제의 핵심 기능을 이해하고 최적화하는 데 필수
