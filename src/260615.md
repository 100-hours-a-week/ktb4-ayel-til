## 1. 네트워크 기초
> 데이터를 송수신하는 기기들 간의 연결을 통해 정보와 자원을 공유할 수 있게 하는 시스템

- 단순히 선으로 연결되어 있는 상태가 아니라, 
- 중요한거는 연결되 장치들이 서로 데이터를 주고 받을 수 있어야 함

### 사용 이유
1. 정보 공유
2. 자원 공유
3. 원격 접속
4. 협업
5. 서비스 제공

**📮 우편 배송 시스템 예시**
- 데이터 = 편지내용
- 패킷 = 편지 또는 소포
- IP 주소 = 도로명 주소
- MAC 주소 = 집 호수 또는 현관 번호
- 스위치 = 아파트 관리실 또는 지역 분류소
- 라우터 = 물류센터
- 인터넷 = 전국, 전세계 배송망

**우리 컴퓨터에서 흐름**
내 컴퓨터에서 -> 브라우저 주소 
- 내 컴퓨터
- -> 공유기(스위치, 라우터)
- -> 통신사 네트워크
- -> 여러 개의 지역 라우터
- -> 목적지 라우터
- -> 목적지 서버
- -> 응답
- 브라우저 주소 입력 하면 웹 페이지가 보인다
- 실제로는 내부에서 데이터가 작은 단위로 쪼개지고, 여러 경로를 따라가서 목적지 도달했다
  - 다시 돌아오는 과정

### 필요한 구성
1. 장치 (Node) (PC, 프린터 등)
2. 네트워크 인터페이스 (유선 LAN 카드, Wi-Fi 모듈 등)
3. 연결 매체 랜 케이블, Wi-Fi, 광케이블 등)
4. 주소 (IP 주소, MAC 주소 등)
5. 네트워크 장비 (스위치, 라우터, 공유기 등)
6. 통신 규칙 (TCP/IP, HTTP, DNS 같은 프로토콜)

**‼️ 인터넷과 네트워크는 무슨 차이?**
- 네트워크: 장치들이 서로 연결되어 데이터를 주고 받는 구조(집 Wi-Fi, 회사 내부망)
- 인터넷: 전 세계의 네트워크들이 서로 연결된 거대한 네트워크(유튜브 시청, 온라인 게임)

**백엔드 개발자 관점**
- API 장애 원인을 빠르게 찾기 위해
- DB 연결 문제를 해결하기 위해
- CORS 같은 웹 통신 오류를 이해하기 위해
- 특정 API 실패 원인을 추적하기 위해
- 배포 후 접속 문제를 해결하기 위해

‼️ 백엔드 개발자는 장애 분석과 문제 해결을 위해 네트워크를 알아야 한다.

**인프라 엔지니어 관점**
- 서버를 외부에 공개하기 위해
- 사내망과 외부망을 안전하게 분리하기 위해
- 장애 발생 시 네트워크 문제를 추적하기 위해
- 클라우드 인프라를 구성하기 위해
- 보안 정책과 접근 제어를 설계하기 위해

‼️ 인프라 엔지니어는 시스템 구축·운영·보안을 위해 네트워크를 알아야 한다.

**💡정리**

네트워크 = 연결된다, 인터넷이 된다 안된다 X
> 내 프로그램이 다른 프로그램과 어떻게 연결되고, 어떻게 데이터를 주고 받는지 이해하는 기반 지식을 이해해야한다.

- 네트워크 : 여러 장치가 연결되어 데이터를 주고받는 구조
- 목적 : 정보 공유, 자원 공유, 원격 접속, 서비스 제공
- 인터넷 : 전 세계 네트워크가 연결된 거대한 네트워크
- 개발자에게 중요한 이유 : API, 서버, DB, 배포, 장애 대응이 모두 네트워크 위에서 동작하기 때문
- 핵심 관점 : "내 코드가 어디로 요청을 보내고, 응답이 어떤 경로로 돌아오는가?"를 이해하는 것

**실무에서 디버깅 방식**
1. 물리적인 연결 되어 있나?
2. IP 주소가 유효한지
3. 목적지로 갈 수 있나?
4. 포트가 열러 있나?
5. 애플리케이션이 응답하는가?

## 2. 노드
> 네트워크에서 데이터를 생성, 수신, 또는 전송하는 장치나 지점

### 사용 이유
- 노드가 있어야 네트워크에서 데이터가 흐른다
  - 네트워크는 단순히 케이블이나, wifi만 있다해서 완성되는게 아니다
  - 그 안에서 데이터를 주고 받는 장치들이 있어야 한다
  - 컴퓨터 -> 공유기 -> 인터넷 -> 웹 서버
- 단순 케이블은 노드가 아니다
  - 데이터를 직접 생성, 수신, 판단 해야함

**💬 카카오톡 예시**
- 메시지를 보내는 장치 -> 내 스마트폰
- 집 안에서 데이터를 전달하는 장치 -> Wi-Fi 공유기
- 중간에서 데이터를 전달하는 장치 -> 통신사 라우터
- 메시지를 처리하는 장치 -> 카카오 서버
- 메시지를 받는 장치 -> 친구 스마트폰

💡 노드는 메세지를 지나가는 과정에서 데이터를 보내거나 받거나 전달하는 지점이다.

#### 호스트
- 사용자 대신해서 실제 데이터를 생성하거나 소비하는 장치 (ex. PC, 서버, 노트북)

- 노드: 네트워크에서 데이터를 송수신하거나 전달하는 모든 장치 또는 지점	(PC, 서버, 라우터, 스위치, 프린터)
- 호스트: 네트워크에 연결되어 서비스를 사용하거나 제공하는 최종 장치 (PC, 스마트폰, 웹 서버, DB 서버)

💡 노드가 더 넓은 개념이고, 호스트는 통신의 출발지 또는 목적지가 되는 장치다.
노드는 출발지와 목적지를 모두 포함하고, 중간에서 데이터를 전달하는 장치까지 포함한다.

**❓ 웹 개발에서의 노드란?**
1. 클라이언트
2. 서버
3. 라우터
4. 스위치

**노드의 특징 = 주소를 가짐**
- 네트워크 상에서 노드를 구분하려면 주소가 필요하다.
- 대표적으로 두 가지 주소
1. MAC : 네트워크 인터페이스 카드에 부여된 물리적인 식별자 - 기기의 고유 일련번호
2. IP : 네트워크 상에서 위치를 나타내는 논리적인 주소 - 도로명 주소

**MAC, IP 주소를 같이 쓰는가?**
- 맥 주소만으로는 한계가 있다
- 맥 주소는 같은 네트워크 안에서만 사용
- 다른 네트워크랑 통신할 때는 IP 주소 사용
- 네트워크 통신에서는 두 가지 주소를 역할을 나눠서 사용

1. IP: 목적지가 어느 네트워크에 있는지 찾을 때
2. MAC: 같은 네트워크 안에서 최종 장치를 찾을 때

**실무에서의 노드**
- 장애가 발생하면 어떤 "노드"에서 장애가 발생했는가?
  - 로드밸런서, API 서버, 프록시 서버, 클라이언트 브라우저, 데이터베이스

- 클라우드에서의 노드
- AWS, CloudFront, WAF, ALB, EC2, RDS, ElastiCache

💡 정리
- 네트워크 = 노드들이 연결되어 데이터를 주고 받는 구조
  - 노드가 없으면 네트워크도 없다.
  - 단순히 연결할 수 있는 통로만 있으면 ≠ 네트워크
  - 노드가 있어서 서로 통신할 수 있을 때 = 네트워크

- 노드 : 네트워크에서 데이터를 보내거나 받거나 전달하는 장치 또는 지점
- 대표 예시 : PC, 스마트폰, 서버, 라우터, 스위치, 프린터
- 필요한 이유 : 노드가 있어야 데이터 송수신이 가능하기 때문
- 호스트와 차이 : 호스트는 주로 서비스를 사용하거나 제공하는 최종 장치, 노드는 더 넓은 개념
- 실무 중요성 : 장애 분석, 서버 구성, 클라우드 네트워크 설계의 기본 단위가 됨

## 3. LAN (Local Area Network)
> 집, 사무실, 학교처럼 제한된 공간 안에서 여러 컴퓨터와 장치를 연결한 내부 네트워크
- 가까운 범위 (건물, 사무실) 안에서 데이터를 주고 받기 위한 네트워크

- LAN = 네트워크
  - 인터넷을 의미하지않음
  - 인터넷 연결이 없더라도 네트워크 안에서 서로 통신하면, LAN이라고 한다
- 군대, 특정 기업 안에서 있는 내부망
  - 외부 인터넷망이랑 연결이 없다
  - 외부 인터넷망 연결한다 = 내부에서 외부를 접근, 외부에서 내부를 접근할 수 있다
- 인터넷 연결이 없어도 "노드들간에 통신을 한다" = LAN

### 사용이유
1. 빠른 내부 통신
2. 자원 공유
3. 관리 편의성
4. 비용 절감

### LAN의 구성 예시
1. PC, 서버, 프린터 등 : 네트워크에 참여하는 장치
2. NIC : 장치가 네트워크에 연결되기 위한 네트워크 인터페이스
3. 스위치 : 같은 LAN 안의 장치들을 연결하고 데이터를 적절한 장치로 전달
4. 라우터/공유기 : LAN과 외부 인터넷을 연결
5. 이더넷 케이블 또는 Wi-Fi : 장치들이 데이터를 주고받는 물리적/무선 연결 방식
6. IP 주소 : LAN 안에서 장치를 구분하기 위한 논리적 주소
7. MAC 주소 : 같은 네트워크 구간에서 장치를 식별하기 위한 물리적 주소

‼️LAN 네트워크 사용하면 인터넷을 거치지 않는다 <- 상당히 큰 장점

### LAN 통신에서 알아야하는 포인트
1. 보통 같은 네트워크 대역대를 가진다
- 대역대 <- IP 주소를 할당
  - CIDR, Address 할당
- 보통 같은 LAN 안에 있는 노드들은 같인 사설 IP대역을 사용함

2. LAN 내부 통신 - 인터넷 통신은 다르다
- 웹 내부 통신은 같은 네트워크 안에서 노드들끼리 통신
- 인터넷 통신은 LAN 벗어나서 외부에 있는 노드랑 통신
- 네트워크 장치
  - 라우터 = 인터넷에서 특정 IP까지 갈 수 있는 경로를 찾는 장치
  - LAN 통신에서는 라우터가 필요 없고, 인터넷 통신할 때는 라우터 사용
- 내 컴퓨터가 LAN에 연결된 프린터를 사용한다 = LAN 통신
- 내 컴퓨터가 구글에 접속한다 = 인터넷 통신

**백엔드 개발자 관점**
- 배포, 장애 대응
- 로컬 서버 실행 → 내 PC 안에서 실행한 서버
  - localhost로 띄운 서버에 접속할 수 있다(인터넷 통해 X)

장점
1. 보안성이 좋아진다
2. 통신 속도가 빨라짐
3. 비용도 안낸다
- 데이터베이스 접속 <- 개발적인 디버깅 할 때

**인프라 엔지니어 관점**

- LAN 설계는 네트워크 설계의 출발점
- 컴퓨터, 프린터, 서버 등을 목적에 맞게 분리하여 네트워크를 구성
- 서버실 네트워크를 구축하고 운영
- LAN 단위로 장애를 분석하고 대응
- 보안 설계 및 성능 이슈를 관리

💡정리
- 제한된 공간 안에서 장치들이 빠르게 통신하고 자원을 공유하기 위한 내부 네트워크

핵심
1. 범위가 작다
2. 내부통신 빠르다
3. 자원공유 쉽다

## 4. WLAN (Wireless Local Area Network)
> LAN 케이블 대신, 무선 신호(와이파이)로 연결한 네트워크

### 사용이유
1. 이동성
2. 설치 편의성
3. 공간 활용
4. 다양한 장치 기원

### 구성
1. 무선 단말 (노트북, 스마트폰, 태블릿, IoT 장치)
2. 무선 NIC  (장치가 Wi-Fi에 연결되기 위한 네트워크 인터페이스)
3. AP, Access Point (무선 장치들을 네트워크에 연결해주는 장비)
4. SSID (사용자가 보는 Wi-Fi 이름)
5. 인증/암호화 (비밀번호, WPA2/WPA3 같은 무선 보안)

### 주의할 점
1. 신호 간섭
2. 보안 문제
3. 속도 변동
4. AP 과부화
5. 음영 지역

- 클라이언트 디바이스가 접속하는 방식이 항상 WLAN 확정
- 백엔드에서는 실시간성이 필요하다 = 신호 간섭이나, 음영지역에서 연결이 제대로 안될 떄 어떻게 처리할지

## 5. VLAN(Virtual Local Area Network)
> 하나의 물리적인 네트워크를 여러 개의 독립된 네트워크처럼 나누는 기술

### 개념
- LAN - WLAN: 어떻게 연결하는지 차이 (유선, 무선)
- LAN - VLAN: 연결된 네트워크를 어떻게 나누는지

- LAN: 가까운 공간의 장치들을 연결
- WLAN: 그 연결을 무선으로 제공
- VLAN: 연결된 네트워크를 논리적으로 분리

### 사용이유
1. 보안 강화
2. 트래픽 감소
3. 관리 편의성
4. 비용 절감

**브로드캐스트란?**
- 같은 네트워크 안의 모든 장치에게 보내는 통신
- 브로드캐스트 도메인: 브로드캐스트가 전달되는 범위
- 브로드캐스트 스톰: 브로드캐스트가 과도하게 발생하여 네트워크 성능이 저하되는 현상
- VLAN의 역할: 브로드캐스트 도메인을 논리적으로 분리

### 주의사항
1. VLAN만으로 완전한 보안은 아님
2. VLAN 간 통신은 별도 설정 필요
3. 설정 실수 위험
4. 운영 복잡도 증가
5. 게스트망 분리 필수

### 사용이유

3. LAN보다 넓은 범위 지원

사용처
- 대학교 내 네트워크 통합
- 도시 내 여러 지점을 가진 회사

**‼️ 통신 규모가 넓어질수록 비용이 높아지고 속도가 느려진다. LAN으로 할 수 있는 통신을 위주로 설계하는 것이 좋다.**

## 1. 네트워크 장비

### 알아야 하는 이유
- 네트워크 통신은 컴퓨터 한 대가 혼자 처리하는 것이 아니다
- 여러 네트워크 장비가 역할을 나눠서 협력 구조
- 네트워크 장비를 배우는 이유는 데이터가 어떤 장비를, 어떤 기준으로 판단해야 문제를 해결할 수 있다.

### 기본적인 흐름
1. 호스트에서 데이터 발송

2. NIC (Network Interface Card)
- 노드들이 네트워크에 연결될 수 있게 하는 하드웨어 (NIC, MAC 주소 갖고 있다)
  - 노트북 와이파이 칩, 데스크톱 랜카드, 서버의 어터넷 포트, 클라우드 VM, 가상 NIC, MAC

리피터: 신호가 약해진 증폭하거나 재생해서 멀리 전달하는 장치

허브: 여러 장치를 연결하는데, 연결된 모든 장치에 데이터를 전달한다

3. 스위치
- 여러 장치 연결하는데, 특정 장치에만 데이터를 전달

4. 라우터
- 다른 네트워크로 가는 길을 정하는 장치
- IP 주소를 기준으로 데이터가 어느 네트워크로 가야하는지 경로를 정하는 장치

게이트웨이: 서로 다른 네트워크, 프로토콜 사이에서 통신 가능하도록 중계 장치

5. 인터넷

## 2. NIC (Network Interface Card)
> 컴퓨터, 서버, 또는 기타 네트워크 장치가 네트워크에 연결되도록 해주는 하드웨어 구성 요소

- NIC는 호스트(PC, Mobile, 장치) 랑 네트워크 사이에서 데이터를 보내고 받는 역할

### 종류
1. 유선 NIC
- 컴퓨터, 서버 등 고정 장치에 사용
- 연결할 때는 이더넷 케이블 
- 무선보다 안정적이고 빠르다

2. 무선 NIC
- Wi-Fi 연결 시 사용
- 노트북, 스마트폰 등 이동성이 있는 장치에 사용

### MAC Address
- NIC에 부여된 고유한 물리적 식별자
- NIC 제조 시 하드웨어에 내장됨
- IP 주소는 변경될 수 있지만 MAC Address는 기본적으로 유지됨

--

## 3. MAC Address (Media Access Control Address)
> 네트워크 장치의 NIC에 부여된 물리적 식별자로, 같은 네트워크 안에서 장치를 구분하는 주소

```
00:1A:2B:3C:4D:5E
└──────┘ └──────┘
 제조사    장치 식별 부분
```

### 맥 주소의 개념
- 네트워크 장치가 가진 고유한 식별 번호 (ex. 제품의 일련 번호)
- LAN 안에서 장치를 식별하고 데이터를 전달할 때 사용
- NIC마다 하나의 MAC Address를 가짐
- NIC가 여러 개라면 MAC Address도 여러 개 존재

📮 우체국 예시
- IP -> 도로명 주소: 공개되어 있고, 알기 쉬운 주소
- MAC Address: 동네에서 우리집만을 구별할 수 있는 고유한 식별 번호

### 사용이유
- IP 주소는 목적지 네트워크를 찾기 위한 주소
- MAC Address는 같은 네트워크 안에서 실제 장치를 찾기 위한 주소

### IP, MAC Address가 무슨 차이가 있나?
#### MAC 주소
- 네트워크 인터페이스의 물리적 식별자
- 데이터 링크 계층(L2) 사용
- 같은 LAN 내부 통신에 사용
- 기본적으로 하드웨어에 부여됨 (스푸핑 가능)
- 예시: `00:1A:2B:3C:4D:5E`
- 관련 장비: 스위치, 브리지, AP

#### IP 주소
- 네트워크 상의 논리적 위치 주소
- 네트워크 계층(L3) 사용
- 네트워크 간 경로 결정에 사용
- 네트워크 환경에 따라 변경 가능
- 예시: `192.168.0.10`
- 관련 장비: 라우터, L3 스위치

### 실제로 맥 주소로 통신
- LAN 내부 통신 시 목적지 MAC 주소가 필요
- ARP(Address Resolution Protocol)를 통해 IP 주소에 해당하는 MAC 주소를 조회


### 맥 주소는 어디까지 사용할까?
- 같은 네트워크(LAN) 구간에서만 사용
- 외부 서버와 통신할 때는 최종 목적지의 IP 주소를 사용
- 실제 전송은 다음 장비(공유기, 라우터)의 MAC 주소를 이용하여 전달

### MAC Spoofing
> 원래 MAC 주소를 다른 MAC 주소처럼 보이게 하는 기술
- 테스트 및 디버깅
- 장치 교체 시 기존 MAC 주소 임시 사용
- MAC 기반 접근 제어 우회
- 장치 추적 회피
- 공유기 가로채기

## 4. 리피터
> 네트워크에서 신호를 증폭하거나 재생하여 더 먼 거리로 전달하는 장치

### 사용이유
1. 신호 감쇠 방지
2. 네트워크 거리 안정
3. 통신 안정성 향상
4. 물리적 제약 보완

### 리피터가 동작하는 계층
- 동작 계층: OSI 1계층, 물리 계층
- 다루는 대상: 비트, 전기 신호, 광 신호, 무선 신호
- 보지 않는 정보: MAC 주소, IP 주소, TCP 포트, HTTP 요청 내용

**증폭, 재생**
증폭 : 약해진 신호의 세기를 키움
재생: 흐트러진 신호를 원래 신호 형태에 가깝게 다시 만듦

### 한계 지점
1. 트래픽을 구분하지 못함
2. 불필요한 신호도 전달
3. 네트워크 충돌 문제 해결 불가
4. 보안 제어 불가
5. 현대 LAN에서는 사용 빈도 낮음

## 5. 게이트웨이
> 서로 다른 네트워크를 연결하여 통신을 가능하게 하는 장치

- 네트워크의 입구, 출입구 역할
- 내부 네트워크와 외부 네트워크를 연결

### 개념
- 네트워크의 경계 지점
- 같은 LAN 내부가 아닌 외부 네트워크와 통신할 때 사용
- 일반적으로 공유기가 기본 게이트웨이 역할을 수행

### 사용 이유
1. 서로 다른 네트워크를 연결하기 위해
2. 데이터 변환 및 필터링을 위해

### 공유기, 라우터와 게이트웨이의 차이
#### 공유기
- 라우터
- 게이트웨이
- 스위치
- 허브

#### 라우터와 게이트웨이
- 라우터 목적지 IP를 보고 다음 경로를 결정 
- 게이트웨이 서로 다른 네트워크 사이의 출입구 역할 

## 게이트웨이의 종류
### 1. 기본 게이트웨이
- 외부 네트워크와 연결되는 출입구
- 내부 네트워크에서 외부 네트워크로 요청을 보낼 때 사용
- 목적지를 찾을 수 없으면 기본 게이트웨이로 전달

### 2. API Gateway

## ‼️6. 라우터
> 서로 다른 네트워크를 연결하고, IP 주소를 보고 패킷이 갈 다음 경로를 결정하는 장비

- 경로를 결정하는 장비
- 패킷을 목적지까지 전달하기 위한 길을 찾음

### 핵심 개념
### 1. 라우터는 “다른 네트워크로 보내는 장비이다”
- 스위치: 같은 LAN 안의 장치들을 연결
- 라우터: 서로 다른 네트워크를 연결

### 라우터는 IP를 보고 판단
- 목적지 IP 주소를 보고 다음 경로를 결정
- 네트워크 계층(L3)에서 동작
- 목적지 IP 기반으로 패킷을 전달

- 스위치: MAC 주소를 보고 같은 LAN 안에서 전달
- 라우터: IP 주소를 보고 다른 네트워크로 전달

### 사용 이유
- 인터넷은 하나의 네트워크가 아닌 여러 네트워크가 연결된 구조
- 라우터는 네트워크와 네트워크 사이에서 패킷이 다음에 어디로 가야 할지 결정

### 라우터 기본 구조
- WAN 포트: 통신사 모뎀, 외부 인터넷  외부 네트워크 방향 
- LAN 포트: PC, 스위치, 내부 장치 내부 네트워크 방향 
- Wi-Fi: 스마트폰, 노트북 내부 무선 네트워크 방향 

### 라우터 동작 방식
1. 패킷을 받는다.
  - 출발지 IP
  - 목적지 IP

2. 목적지 IP를 확인한다.
- 어느 네트워크로 보내야 하는지 판단

3. 라우팅 테이블을 확인한다.
- 목적지와 가장 일치하는 경로를 선택

4. 다음 라우터 또는 목적지로 전달한다.
- 규칙: 현재 패킷이 가고 싶은 목적지랑 가장 유사하게 구체적인 라우팅 경로로 이동

### 라우터는
> "최종 목적지까지 한 번에 보내는 장비가 아니다"
- 다음에 전달할 가장 적절한 라우터를 선택
- 이를 Hop이라고 함
- 라우터는 최종 목적지가 아니라 다음 홉을 안내


### 라우터에서의 기본 개념
#### 패킷
- 네트워크 계층에서 사용하는 데이터 단위
- 출발지 IP, 목적지 IP 포함

#### 라우팅
- 목적지까지 패킷이 가도록 경로를 결정하는 과정

#### 라우팅 테이블
- 라우터가 참고하는 경로 정보

#### 기본 경로 (Default Route)
- 적절한 경로를 찾지 못했을 때 사용하는 경로
  - 0.0.0.0/0 → ISP

### 게이트웨이와 라우터

#### 게이트웨이
- 서로 다른 네트워크의 출입구
- 네트워크 연결, 변환, 필터링, 중계 수행
- 라우터가 게이트웨이 역할을 할 수 있음

#### 라우터
- IP 기반 경로 선택 장비
- 패킷의 다음 경로 결정
- 게이트웨이 기능을 포함할 수 있음

### 라우팅 테이블은 어떻게 만들어지는가?
- 직접 연결 경로: 라우터 인터페이스 IP를 설정하면 자동 등록
- 정적 라우팅: 관리자가 직접 경로 입력
- 동적 라우팅: 라우터끼리 경로 정보를 교환 

### 동적 라우팅
- 라우터들이 서로 경로 정보를 주고받음

- OSPF: 회사 내부망, 데이터센터 내부
- RIP: 교육용, 소규모 환경
- BGP: 조직과 조직 사이의 경로 교환
- IS-IS: 대규모 내부망에서 사용

## 7. 허브 (Hub)
> 여러 장치를 하나의 네트워크에 연결하고, 들어온 데이터를 모든 장치에게 전달하는 장비

### 사용 이유
- 여러 장치를 네트워크에 연결하기 위해 사용
- 가장 단순한 연결 장비

### 특징
- 들어온 데이터를 모든 포트로 전달
- 목적지를 구분하지 못함

### 장점
- 저렴함
- 구성이 단순함

### 단점
- 불필요한 트래픽 증가
- 보안에 취약
- 충돌 발생 가능성 높음

---

## 8. 스위치 (Switch)
> 같은 네트워크 안에서 MAC 주소를 보고 데이터를 필요한 장치에게만 전달하는 장비

### 특징
- MAC Address Table을 관리
- 목적지 MAC 주소를 기준으로 전달

- 동작 계층: 데이터 링크 계층(L2)
- 보는 정보: MAC 주소
- 데이터 단위: 프레임(Frame)

### 스위치 동작 방식

#### 1. 목적지 MAC 주소를 알고 있을 때
1. 목적지 MAC 주소 확인
2. MAC Address Table 조회
3. 해당 포트로만 전달

#### 2. 목적지 MAC 주소를 모를 때
- Flooding 수행
- 모든 포트로 전송
- 응답을 받으면 MAC Address Table 갱신

### Flooding과 Broadcast 차이

#### Broadcast
- 모든 장치가 목적지
- 모든 장치에게 전송

#### Flooding
- 목적지 MAC 주소를 몰라서 전송
- 모든 포트에 전송 후 응답을 기다림

### 사용 이유
- 정확한 데이터 전달
- 불필요한 트래픽 감소
- 충돌 감소
- 성능 향상
- 보안 향상

## 9. 브릿지
> 두 개 이상의 LAN 세그먼트를 연결하고, MAC 주소를 기준으로 필요한 트래픽만 전달하는 장비

### 특징
- LAN과 LAN을 연결
- MAC 주소를 기준으로 전달
- 같은 LAN이면 내부 처리
- 다른 LAN이면 연결된 LAN으로 전달

### 사용 이유
1. 여러 LAN 연결
2. 불필요한 트래픽 감소
3. 충돌 범위 감소

### 브릿지와 스위치
#### 공통점
- L2 장비
- MAC 주소 기반 동작

#### 차이점
- 브릿지: LAN 세그먼트 연결
- 스위치: 여러 장치를 LAN 내부에서 연결

- 브릿지는 포트 수가 적고 소프트웨어 기반
- 스위치는 포트 수가 많고 하드웨어 기반
