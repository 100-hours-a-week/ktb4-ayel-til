## 데이터베이스
- 데이터를 기록하고 싶은데 어떻게 해야할까?
  - 천공카드

### 파일시스템 단점
- 데이터 기록이 중복
- 파일이 커지면 찾기 힘듦
- 보안, 권한이 부족
- 동시에 수정이 불가능
- 데이터가 잘못 적혀 있을 수도 있음
- 다른 OS에서 제대로 안 읽힘

## 데이터베이스 등장
- 데이터 기록이 중복  
  -> 중복/불일치 최소화 (중앙 집중 관리)

- 파일이 커지면 찾기 힘듦  
  -> 인덱스 같은 자료구조로 빠르게 탐색 (효율적 검색)

- 보안, 권한이 부족 
  -> 사용자/DB별 권한 제어 가능 (높은 보안성)

- 동시에 수정이 불가능  
  -> 트랜잭션과 락으로 충돌 방지 (동시성 제어)

- 데이터가 잘못 적혀 있을 수도 있음  
  -> 데이터 규칙을 강제 (무결성 제어)

- 다른 OS에서 제대로 안 읽힘  
  -> 모든 OS에서 동작하는 시스템 (호환성)

---

  - 관계형 데이터베이스를 관리하는 프로그램
  
---

## ERD

### 사용 이유
- 설계를 명확하게 하기 위해서
- 팀 간 소통을 정확하게 하기 위해서
- 설계 의도를 공유하고 유지하기 위해서
- 구현 전에 문제를 발견하기 위해서

### 순서
1. 정보(개념적) 모델링
2. 논리적 모델링
3. 데이터베이스 구현

### ERD 표기법
- Crow’s Foot Notation (까마귀 발 표기법)
- Peter Chen Notation (피터 챈 표기법)
- Barker Notation (바커 표기법)

### 관계 표기
1. Zero
  - 관계가 필수적이지 않다
2. One
  - 최소 한 개의 관계를 가질 수 있다
3. Many
  - 여러 개의 관계를 가질 수 있다
4. Zero or Many
  - 0개 또는 여러 개의 관계를 가질 수 있다
5. One or Many
  - 최소 1개 또는 여러 개의 관계를 가질 수 있다
6. One and only one
  - 하나의 관계만 가져야 한다
  - 최소값, 최대값 모두 1개
  - ex) 학생증

## 인덱스(Index)
- 조회 속도를 높이기 위해 사용하는 기술

### 사용 이유
- 인덱스를 사용해 데이터를 정렬하면 매우 빠르게 정렬된 결과를 출력할 수 있기 때문에 사용한다

---

## HASH Index

### 개념
- 입력 값에 따라 같은 출력을 가짐  
  -> key → hash
- 버킷에 인덱스 값으로 매핑되어 찾고자 하는 데이터를 얻기 쉬움
- 미리 저장된 메모리에 접근하기에 탐색 시간이 가장 빠름

### 장점
1. 단일 검색 속도가 가장 빠르다

2. 인덱스 크기의 효율성이 좋다

### 단점
1. 범위 검색 불가능하다

2. 부분 일치 검색이 안된다

3. 정렬, 그룹화 불가능

### 해시 충돌 문제
- 서로 다른 키 값이 -> 해시 함수를 거친다
- 충돌이 많이 나면, 성능이 급격히 안좋아진다
- 해시 값이 무작위이기 때문에 범위 검색이 힘듦
- 해시 충돌 해결이 어려움

### 해결 방식
- 체이닝(Linked List)

### 어디에 사용되나?
1. in-memory DB에서 많이 사용된다

2. RDB에서 내부 알고리즘 최적화

## B-Tree vs B+Tree

> 핵심적인 차이  
-> 노드에 키와 데이터 주소(value)를 같이 저장하느냐의 차이

---

## B-Tree

### 개념
> 노드마다 데이터를 다 들고 다닌다

- 루트 노드, 중간 노드, 리프 노드
- 모든 노드가 인덱스 키 + 실제 데이터 주소를 같이 저장

### 장점
- 다양한 쿼리에 효율적으로 작동
- 트리 균형으로 어떤 데이터든 일정하게 탐색 가능

### 단점
- 노드 크기가 크다
- 트리 깊이가 깊어질 수 있다
- 균형을 맞추기 위한 노드 분할, 병합 비용 발생
- 구조 유지 비용 존재

---

## B+Tree

### 개념
> 중간에는 키만 두고, 데이터는 리프 노드에만 몰아두는 구조

- 리프 노드에만 주소 값을 갖고 있다
- 중간 노드는 인덱스 키 + 자식 노드 포인터만 가진다
- 실제 데이터는 리프 노드에 저장된다

### 장점
- 범위 검색에 유리
- 디스크 접근 감소

### 특징
- 리프 노드는 인접한 형제 노드와 Linked List 형태로 연결되어 있다
- 실제 데이터는 리프 노드에 모여 있다
- MySQL InnoDB 엔진의 기본 자료구조
---
|  | B+Tree | Hash Index |
| --- | --- | --- |
| 자료 구조 | 균형 잡힌 트리 (tree) | Hash Table |
| 단일 검색 성능 | O(log N) ← 성능이 준수하다. | O(1) ← 제일 빠름 |
| 범위 검색 | O(log N)  | 불가능 |
| 주요 용도 | RDB 주요 엔진 | NoSQL, 캐시, 알고리즘 최적화 |

## 트랜잭션
- 데이터베이스의 상호작용의 단위
- 일 처리의 최소 단위

### 사용이유
- 데이터베이스의 무결성과 일관성 보장하고,
- 여러 작업을 하나의 논리적인 작업 단위로 묶어서 처리하기 위해서

### 개념
- 한꺼번에 수행할 연산을 모아 놓은 것
- 연산을 성공하지 못하면 처음으로 돌아감

### 상태
1. Active(활성)
2. Partially Committed(부분 완료)
3. Committed(완료)
4. Failed(실패)
5. Aborted(철회)

## 무결성
-> "데이터"에 결함이 없는 상태
- 데이터베이스에 저장된 데이터가 "정확하다", "유효하다", "신뢰성이 있다"

## 일관성
- 모순이 없다. 규칙을 준수한다
-> 작업전후에 상태가 일관적이다.

---

## ACID
- 트랜잭션이 안전하게 수행된다는 것을 보장하기 위해 4가지 특징

### Atomicity (원자성)
- 트랜잭션이 완벽하게 수행되거나 전혀 수행되지 않아야 한다.

### Consistency (일관성)
- 트랜잭션의 작업 처리 결과는 항상 일관성과 정합성이 보장되어야 한다.

### Isolation (고립성)
- 동시에 다수 쿼리가 발생하는 경우 모든 쿼리 당 트랜잭션은 독립되어야 한다.

### Durability (지속성)
- 트랜잭션이 성공적으로 완료되었으면, 결과는 영구적으로 반영되어야 한다.

## Isolation Level
- Isolation Level은 Transaction 독립(고립)의 정도에 대한 정의다
