# RDBMS

## 1. RDBMS란 무엇인가

**관계형 데이터베이스**(Relational Database, RDB)는 데이터를 행(Row)과 열(Column)로 구성된 테이블 형태로 저장하고, 테이블 간의 관계를 통해 데이터를 관리하는 데이터베이스 모델이다.

1970년대 에드거 프랭크 코드(E.F. Codd)가 제안한 관계형 모델을 기반으로 하며, **기본 키(Primary Key)**와 **외래 키(Foreign Key)**를 사용하여 데이터 간의 연관성을 표현한다.

이러한 관계형 데이터베이스를 실제로 생성, 수정, 삭제 및 관리할 수 있도록 지원하는 소프트웨어를 **관계형 데이터베이스 관리 시스템(RDBMS)**이라고 한다.

대표적으로 MySQL, PostgreSQL, Oracle Database 등이 있으며, 오랜 기간 데이터 관리의 표준 기술로 사용되어 왔다.

RDBMS가 널리 사용된 가장 큰 이유는 데이터의 **무결성과 일관성**을 강력하게 보장하기 때문이다.

또, SQL이라는 언어를 통해 데이터를 효율적으로 조회하고 관리할 수 있으며, 정규화를 통해 데이터 중복을 최소화할 수 있다.

---

## 2. RDBMS의 특징과 장점

RDBMS의 가장 큰 특징은 **ACID**를 준수한다는 점이다.

ACID는 **원자성**(Atomicity), **일관성**(Consistency), **격리성**(Isolation), **지속성**(Durability)을 의미하며, 트랜잭션이 안전하게 수행되도록 보장하는 핵심 특성이다.

이를 통해 시스템 장애가 발생하더라도 데이터 무결성과 일관성을 유지할 수 있다.

이러한 특징으로 인해 다음과 같은 장점을 가진다.

1. SQL을 사용하여 복잡한 데이터를 효율적으로 조회하고 조작 가능
2. 정규화를 통해 데이터 중복을 최소화하고 데이터 일관성을 유지함
3. 다중 사용자 환경에서 잠금 기능을 제공하여 동시 작업 시 데이터 충돌을 방지
4. 권한 제어 기능을 통해 데이터 접근을 효율적으로 관리

---

## 3. RDBMS의 한계

인터넷 서비스의 성장과 함께 데이터의 양과 종류가 급격히 증가하면서 기존 RDBMS의 한계가 점차 드러나기 시작하였다.

RDBMS는 **고정된 스키마를 기반으로 동작**한다.

따라서 데이터 구조가 자주 변경되거나 비정형, 반정형 데이터를 다루는 환경에서는 유연성이 떨어진다.

특히 이미지, 로그 데이터, JSON 문서와 같은 데이터는 관계형 모델로 표현하기 어렵다.

확장성 측면에서도 한계가 존재한다.

RDBMS는 기본적으로 단일 서버의 성능을 향상시키는 **수직 확장**에 적합하게 설계되었다.

그러나 대규모 서비스에서는 여러 서버에 데이터를 분산 저장하는 수평 확장이 필요하며, 이 과정에서 데이터 일관성과 트랜잭션을 유지하는 것이 매우 복잡해진다.

성능 측면에서도 문제가 발생한다.

데이터 규모가 증가할수록 JOIN 연산의 비용이 증가하며, 분산 환경에서는 네트워크 병목 현상으로 인해 성능이 저하될 수 있다.

실시간 스트리밍 데이터 처리나 머신러닝, 인공지능 환경에서 요구되는 다양한 형태의 데이터를 처리하는 데에도 제약이 존재한다.

# NoSQL

### 1. NoSQL의 등장 배경

2000년대 후반 웹 서비스와 소셜 네트워크 서비스가 급격히 성장하면서 데이터 환경은 크게 변화하였다.

기존에는 정형 데이터가 대부분이었지만, 사용자들이 생성하는 게시글, 이미지, 동영상, 위치 정보, 로그 데이터 등 다양한 비정형 데이터가 폭발적으로 증가하였다.

동시에 수억 명의 사용자가 접속하는 초대형 서비스가 등장하면서 기존 RDBMS만으로는 처리하기 어려운 규모의 데이터와 트래픽이 발생하였다.

이러한 변화로 인해 기존 데이터베이스 기술만으로는 대응하기 어려운 새로운 요구사항이 등장하였고, 이를 해결하기 위한 새로운 데이터베이스 모델의 필요성이 대두되었다.

이러한 배경 속에서 등장한 것이 NoSQL이다.

---

## 2. NoSQL이란 무엇인가

NoSQL은 일반적으로 "Not Only SQL"의 의미로 사용된다.

SQL을 완전히 배제한다는 의미가 아니라 관계형 데이터 모델 외에도 다양한 데이터 저장 방식을 활용한다는 의미이다.

NoSQL은 **Key-value Store**, **Documents Store**, **Column-Oriented Store**,  **Graph Store**와 같은 다양한 데이터 모델을 제공한다.

또한 고정된 스키마를 강제하지 않기 때문에 데이터 구조가 자주 변경되는 환경에서도 유연하게 대응할 수 있다.

---

## 3. NoSQL의 특징과 장점

RDBMS가 ACID를 통해 강력한 데이터 일관성을 보장하면, NoSQL은 분산 환경의 효율성을 위해 BASE 철학을 따른다.

BASE는 기본 가용성(**Basically Available),** 소프트 상태(**Soft-state),** 최종 일관성(**Eventual Consistency)**의 약자를 의미한다.

시스템의 가용성을 우선적으로 보장하고 데이터가 일시적으로 불일치할 수 있음을 허용하지만, 시간이 지나면 최종적으로 일관된 상태에 도달하도록 하는 접근 방식이다.

NoSQL은 실시간의 완벽한 일관성을 일부 양보하는 대신 높은 확장성과 성능을 얻는 방식을 선택한 것이다. 이는 ACID와 BASE가 서로 다른 우선순위를 가진 설계 철학임을 보여준다.

이러한 특징으로 인해 다음과 같은 장점을 가진다.

1. 유연한 스키마를 통한 높은 개발 생산성
2. 수평 확장을 통한 뛰어난 확장성
3. 대규모 읽기, 쓰기 환경에서의 높은 성능
4. 분산 시스템 환경에서의 높은 가용성
5. 비정형·반정형 데이터 처리 능력

---

# RDBMS와 NoSQL 비교

| 구분 | RDBMS | NoSQL |
| --- | --- | --- |
| 데이터 구조 | 테이블 기반 | 다양한 데이터 모델 |
| 스키마 | 고정 스키마 | 유연한 스키마 |
| 확장 방식 | Scale-Up | Scale-Out |
| 데이터 일관성 | ACID | BASE |
| 적합한 데이터 | 정형 데이터 | 비정형, 반정형 데이터 |
| 강점 | 무결성, 신뢰성 | 확장성, 성능 |

# 결론

RDBMS는 데이터 **무결성과 일관성**을 보장하는 강력한 데이터베이스 시스템으로 오랫동안 데이터 관리의 표준으로 사용되어 왔다.

그러나 인터넷 서비스의 성장과 데이터 규모의 증가로 인해 **고정 스키마, 수평 확장의 어려움, JOIN 성능 저하** 등의 한계가 나타나게 되었다.

NoSQL은 이러한 한계를 보완하기 위해 등장한 데이터베이스 모델로, 유연한 스키마와 뛰어난 확장성, 높은 가용성을 바탕으로 대규모 분산 환경에 적합한 솔루션을 제공한다.

NoSQL은 RDBMS를 대체하기 위한 기술이 아니라, RDBMS가 해결하기 어려운 문제를 보완하기 위한 기술이라고 볼 수 있다. 현대 시스템에서는 데이터의 특성과 요구사항에 따라 RDBMS와 NoSQL을 함께 활용하는 방식이 널리 사용되고 있다.

RDBMS와 NoSQL는 데이터 **무결성과 일관성**을 우선할 것인지, **확장성과 가용성**을 우선할 것인지에 대한 차이다.

금융 및 결제 시스템과 같이 데이터 무결성이 중요한 환경에서는 **RDBMS**가 적합하다.

SNS, 실시간 로그 처리와 같이 대규모 트래픽과 비정형 데이터를 다루는 환경에서는 **NoSQL**이 적합하다.

우리는 사용 목적에 따라 적절한 데이터베이스를 선택해야 한다.
