## 1. 교착상태 (Deadlock)
> 두 개 이상의 프로세스나 스레드가 자원을 점유한 채 서로가 필요로 하는 자원을 기다리며 무한히 대기하는 상태

### 알아야 하는 이유
1. 시스템 안정성 확보
2. 효율적인 자원 관리
3. 복잡한 분산 환경에서의 신뢰성 확보
4. 동시성 코드 설계

‼️ 교착 상태 <- 가시성이 안 좋은 에러

### 실무에서 어떻게 보이는지
1. DB 트랜잭션: 트랜잭션 A는 row 1을 잠근 뒤 데이터 2를 기다리고, 
트랜잭션 B는 row 2를 잠근 뒤 row 1을 기다림
2. 멀티스레드 코드: 스레드 A는 Lock 1을 획득 후 Lock 2를 기다리고, 
스레드 B는 Lock 2를 획득 후 Lock 1을 기다림
3. 커넥션 풀: 요청들이 커넥션을 점유한 채 다른 커넥션이나 락을 기다림
4. 파일 처리: 여러 스레드가 파일, 버퍼, 메타데이터 락을 서로 다른 순서로 점유

### 교착 상태 발생 조건
1. 상호 배제: 하나의 자원을 한 번에 하나의 프로세스나 스레드만 사용할 수 있음
2. 점유와 대기: 프로세스가 이미 자원을 가진 상태에서 다른 자원을 추가로 기다림
3. 비선점: 다른 프로세스가 점유한 자원을 강제로 빼앗을 수 없음
4. 순환 대기: 자원을 기다리는 관계가 원형 구조를 이룸

### 해결 방법
1. 점유와 대기 줄이기: 필요한 자원을 한 번에 얻거나, 실패하면 기존 자원을 놓고 재시도
2. 순환 대기 방지: 모든 스레드가 자원을 같은 순서로 획득하도록 규칙화

### 예방 방법
1. 락 획득 순서 통일
2. 타임아웃 설정
3. 락 범위 최소화
4. 한 번에 여러 락 잡지 않기
5. 자원 선점 또는 롤백
6. 감시와 복구

**💡 정리**
1. 교착상태 여러 작업이 자원을 점유한 채 서로의 자원을 기다리면서 더 이상 진행하지 못하는 상태
2. 교착상태 발생 조건
   - 1. 상호 배제 b. 점유와 대기 c. 비선점 d. 순환대기
3. 예방법
   - 1. 락 순서를 통일 b. 락과 트랜잭션 시간을 짧게 유지 c. 타임아웃과 재시도를 설계

❓ 교착 상태를 예방하는 방법으로 가장 적절하지 않은 것은?
✅ 락을 잡은 상태에서 오래 걸리는 외부 API 호출을 수행한다

## 2. 기아상태 (Starvation)
> 특정 프로세스나 스레드가 자원을 계속 받지 못하는 상태

### 발생 원인
1. 우선 순위 기반 스케줄링
- 중요한 거 먼저 처리함
- 낮은 우선순위는 계속 밀림

2. 불공정한 락 획득
- 불공정 락의 사용하는 이유는 훨씬 더 저렴하게 운영할 수 있다
- 공정 락은 누가 언제 도착했는지 알아서, 자원으로 관리한다

3. Read_Write에서 Write 기아
- Write Lock은 다른 Read Lock이 모두 해제되어야 획득 가능
- Read가 계속 들어오면 기아 상태 발생

### 해결법
1. 에이징 
> 오래 기다린 작업의 우선순위를 점진적으로 높이는 방식

2. 라운드 로빈 / 타임 슬라이스 방식
>모든 작업한테 일정한 시간 조각을 주고 그 시간만큼 수행하는 방식

⚠️ 공정성은 유리하지만, 컨텍스트 스위칭이 잦을 수 있다

3. 최대 대기 시간 설정
> 일정 시간 이상 기다린 작업은 강제로 실행 기회 부여

4. 공정한 큐 사용하기
> 기아 상태는 "누가 먼저 기다린지" 무시 될 때 발생
- 해결법 a. FIFO 큐 b. FAIR LOCK c. 대기열 기반 처리 

**❓ 백엔드 엔지니어 관점 -> 기아 상태**
- 기아상태 != 운영체제에서 발생
  - 스프링 앱 <- 스레드 풀
  - 데이터베이스 <- 커넥션 풀
  - 락, 큐 

**💡 모든 에러 대응의 대원칙**
> 관측해야 수정한다 -> 옵저빌리티가 높나

**💡정리**
기아상태란 기다리고 있는데 내 차례가 계속 오지 않는 문제

## 3. 세마포어
> 공유자원에 접근할 수 있는 "허가권(Permit)"의 개수를 관리하는 동기화 방법

### 사용이유 
> 공유 자원, 한정된 자원이 너무 많은 작업을 동시 수행하면 장애나 성능 저하가 발생하므로 세마포어로 동시 접근 수를 제한한다

1. 자원 보호: 한정된 자원을 동시에 너무 많이 사용하지 않도록 제한
2. 동시성 제어: 여러 스레드가 동시에 실행되더라도 안전하게 순서를 조정
3. 시스템 안정성: 과도한 요청으로 서버, DB, 외부 API가 무너지지 않게 보호
4. 상황에 맞는 도구 선택

### 핵심 개념
1. 세마포어 값 S 
- S: 현재 사용 가능한 허가권의 개수
- S > 0: 자원을 사용할 수 있음
- S = 0: 모든 자원이 사용 중이므로 대기해야 함

2. P 연산
- 세마포어 값을 감소시키며, 공유 자원을 사용할 수 있는 권한을 감소시킴
- P(wait)는 허가권을 하나 가져가는 연산
- S > 0: S를 1 감소시키고 자원 접근 허용
- S = 0: 더 이상 허가권이 없으므로 대기

3. V 연산
- 세마포어 값을 증가시키며, 공유 자원을 사용할 수 있는 권한을 증가시킴
- V(signal)은 허가권을 하나 반납하는 연산
- 자원 사용 완료: S를 1 증가
- 대기 중인 스레드 있음:	대기 중인 스레드 중 하나가 깨어나 자원 접근 가능

---

### 세마포어 종류
1. 이진 세마포어 (단일)
- 값이 0, 1만 가지는 세마포어

- 구분
  - 값의 범위: 0 또는 1
  - 사용 목적: 단일 자원 접근 제어
  - 예시: 단일 파일 쓰기, 단일 장치 접근
  - 뮤텍스와 차이: 뮤텍스는 소유권 개념, 세마포어는 일반적으로 permit 개념

**💡 뮤텍스는 오너가 잠궜다. 세마포어는 몇개의 허가권이 남았냐**

2. 카운팅 세마포어 (다중)
- 값이 0 이상의 정수로 동작, 여러 개의 자원 접근 제어

- 구분
  - 값의 범위: 0 이상 정수
  - 사용 목적: 다중 자원 접근 제어
  - 예시: DB 커넥션 풀, 스레드 풀, 네트워크 포트, 프린터 여러 대
  - 특징: 동시에 접근 가능한 작업 수를 제한할 수 있음

**헷갈릴만한 개념**
1. 세모파어는 락인가?
- 세마포어는 “락”이 아니라 "허가권 관리"
- 뮤텍스는 화장실 열쇠 1개, 세마포어 식당 테이블 5개 (한 팀이 나가면 한 자리 생김)

💡 세마포어도 상호배제 → **일반적으로는 동시 접근 수 제한에 더 많이 사용된다.**

---

**백엔드 엔지니어**

1. 외부 API 호출 제한 (ex. 제미나이, 구글맵)
- 외부 API 동시 호출 수 제한

2. 파일 · 이미지 처리
- 스레드 풀 개념
- 이미지 처리 작업 수 제한
3. 배치 작업
- 배치 작업 동시 실행 수 제한

**인프라 엔지니어**

1. 로드밸런서
- WS -> WAS로 요청 분산, 서버별 동시 요청 수 제한

2. Nginx
- 웹 서버에 접근할 수 있는 동시 HTTP 연결 수 제한

3. Rate Limit
- 일정 시간 동안의 요청 횟수 제한

**💡정리**
1. 세마포어는 “공유 자원에 몇 명까지 동시에 사용할 수 있는지” 정의하는 동기화 도구 
2. DB 커넥션 풀, 스레드 풀, API 호출 제한 등의 실무 문제의 해결방안

❓세마포어의 P(wait) 연산에 대한 설명으로 가장 적절한 것은?
✅ 공유 자원 접근 권한을 얻기 위해 세마포어 값을 감소시킨다

❓카운팅 세마포어가 가장 적절하게 사용되는 상황은?
✅ 여러 개의 DB 커넥션 중 사용 가능한 커넥션 수를 관리하는 상황

## 4. 리눅스 명령어

### 1. 기초 명령어
1. pwd : 현재 위치 확인
2. ls : 파일 목록 확인
3. cd : 디렉터리 이동
4. mkdir : 디렉터리 생성
5. touch : 빈 파일 생성
6. cp : 파일/디렉터리 복사
7. mv : 파일 이동 또는 이름 변경
8. rm : 파일/디렉터리 삭제
9. cat : 파일 내용 출력
10. less : 긴 파일을 페이지 단위로 조회하기

### Nano, Vi
nano: 텍스트 에디터

### Crontab
- 특정 시간마다 작업을 반복하게 함
- 배치 작억, 로그 정리, 백업, 주기적인 스크립트 실행

**기본 문법**
기본 형식:분 시 일 월 요일 명령

- AWS 에서 서비스 사용

### File Permission
- 현재 사용자가 해당 파일이나 디렉터리에 접근할 권한이 없음

### Pipe
- 명령어를 조합할 때 사용하는 것
- “앞 명령어의 결과를 뒤 명령어의 입력으로 넘긴다.”

### Grep
텍스트 데이터 안에서 특정 패턴과 일치하는 줄을 찾아 출력하는 검색 전용 명령어

### Head / Tail
- 헤드 → 파일의 앞글자만 보여주기
- 테일 → 파일의 뒷글자만 보여주기
- 보통 파일의 중요한 내용은 맨 앞이나, 맨 뒤

### Top
- 실시간으로 시스템의 프로세스 상태, 자원 사용량 모니터링 하는 명령어

### PS
- 현재 실행 중인 프로세스 목록을 출력하는 명령어

### Symbolic Link
- 원본 파일의 경로를 가리키고 있는 링크 파일 (윈도우 바로가기)

### DU / DF
- 디스크 문제 있을 때 디스크 상태
- df: 파일 시스템의 전체 용량을 확인 (“디스크가 몇 퍼센트 찼냐?)
- du: 특정 디렉터리, 파일이 얼마나 차지하는지를 확인 (“누가 디스크를 많이 쓰지?”)
- 실무에서 디스크가 터지는 이유
    - 1. 로그 파일 b. 도커 이미지 c.파일 업로드 → temp 파일 미처리 d. DB e. 백업 파일을 안치우는 경우

### Dig
- DNS 확인

### SS
- 어떤 프로세스가 몇 번 포트 사용중인지 확인
