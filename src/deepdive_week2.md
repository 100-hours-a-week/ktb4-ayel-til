## 3. 키워드 별 딥다이브

### 1. Web Server

초기의 웹은 HTML 문서를 단순히 전달하는 정적 페이지 중심 구조였다. 이 시기의 Web Server는 클라이언트의 HTTP 요청을 받아 저장된 파일을 그대로 반환하는 역할을 했다.

HTTP는 웹에서 클라이언트와 서버가 데이터를 주고받기 위해 사용하는 통신 규약이며, Web Server는 HTTP 요청을 받아 이에 대한 응답을 반환한다.

Web Server가 주로 처리하는 대상은 정적 컨텐츠이다. 정적 컨텐츠란 웹 서버에 미리 저장된 파일(HTML, CSS, JavaScript, 이미지 등)을 사용자의 요청에 따라 별도의 가공 없이 그대로 전달하는 웹 콘텐츠이다.

정적 컨텐츠는 별도의 복잡한 연산 과정이 거의 필요하지 않기 때문에 빠른 응답이 가능하며, 많은 요청도 비교적 효율적으로 처리할 수 있다.

대규모 서비스 환경에서는 이러한 정적 리소스를 더 빠르게 제공하기 위해 콘텐츠 전송 네트워크(CDN)를 사용하기도 한다. CDN은 사용자와 가까운 서버에서 정적 리소스를 제공하여 응답 속도를 향상시키는 기술이다.

대표적인 Web Server에는 NGINX와 Apache가 있다.

---

### 2. Web Application Server(WAS)

웹 서비스가 발전하면서 로그인, 회원가입, 게시글 조회처럼 사용자마다 다른 결과를 반환하는 동적 기능이 필요해졌다.

이러한 기능은 단순 파일 전달만으로 처리할 수 없으며, 서버 측 코드 실행과 데이터베이스 연동 과정이 필요하다. 이 문제를 해결하기 위해 등장한 것이 WAS(Web Application Server)이다.

WAS는 동적 컨텐츠 처리를 담당하는 서버이며, 내부에는 Web Container가 존재한다.

Web Container는 Servlet과 JSP를 실행할 수 있는 환경을 제공하며, 클라이언트의 요청 객체와 응답 객체를 생성하고 관리하는 역할을 수행한다.

- Servlet
  → 클라이언트의 요청을 받아 서버 측 비즈니스 로직을 수행하는 자바 기반 서버 프로그램
- JSP(Java Server Pages)
  → HTML 내부에서 자바 코드를 사용할 수 있도록 만든 서버 측 페이지 기술



동적 요청이 들어오면 Web Container는 요청을 처리할 스레드를 할당하고 Servlet을 실행한다. 이후 Servlet은 서버 사이드 코드를 수행하고 데이터베이스와 연동한 뒤 결과를 반환한다.

이 과정에서 WAS는 요청마다 스레드를 사용하여 동작한다. 각 스레드는 요청 처리가 끝날 때까지 CPU와 메모리 자원을 사용하며, 데이터베이스 응답을 기다리는 동안에도 자원을 계속 점유하게 된다.

대규모 서비스 환경에서는 여러 요청을 효율적으로 처리하기 위해 멀티스레딩 구조를 사용하며, 여러 대의 WAS 서버를 두고 로드 밸런싱을 통해 요청을 분산하여 처리하기도 한다.

- 로드 밸런싱

  → 특정 서버에 요청이 집중되지 않도록 여러 서버에 트래픽을 분산시키는 기술이다.


대표적인 WAS에는 Tomcat이 있다.

---

### 3. 요청 처리 책임 분리

웹 서비스에서는 정적 요청과 동적 요청의 처리 방식이 다르다.

이미지, CSS, JavaScript와 같은 정적 리소스는 별도의 연산 과정 없이 파일만 전달하면 되기 때문에 비교적 가볍게 처리할 수 있다.

하지만 로그인, 회원가입, 게시글 조회와 같은 동적 요청은 서버 측 코드 실행과 데이터베이스 연동 과정이 필요하기 때문에 더 많은 CPU와 메모리 자원을 사용한다.

이러한 차이 때문에 Web Server와 WAS는 요청 처리 책임을 분리하여 동작한다.

---

## 4. 주제 복귀

Web Server와 WAS는 요청 처리 책임을 분리하여 각각의 역할에 맞는 작업을 수행하도록 구성된다.

Web Server는 정적 리소스를 빠르게 처리하고, WAS는 서버 측 코드 실행과 데이터베이스 연동이 필요한 동적 요청을 처리한다.

동적 요청은 요청마다 스레드와 메모리 자원을 사용하기 때문에 정적 요청과 동적 요청을 분리하여 처리하는 구조가 필요하다.

이를 통해 서버 부하를 줄이고 성능과 확장성을 향상시킬 수 있으며, 대규모 서비스 환경에서는 로드 밸런싱을 통해 여러 WAS 서버로 요청을 분산하여 안정적인 서비스 운영이 가능하다.

---

### ⚠️ WAS가 모든 요청을 처리하는 경우

Web Server 없이 WAS가 정적 요청과 동적 요청을 모두 처리한다면 이미지나 CSS 파일 요청에도 WAS의 스레드가 사용된다.

이러한 상황에서 많은 사용자가 동시에 접속하면 정적 파일 요청만으로도 WAS의 스레드가 빠르게 점유될 수 있다. 결과적으로 중요한 동적 요청이 대기 상태에 들어가게 되고, 서버 응답 속도 저하나 성능 문제가 발생할 수 있다.

따라서 Web Server는 정적 요청 처리에 집중하고, WAS는 동적 요청 처리에 집중하도록 역할을 분리한다.

---

### 장점

- 정적 요청과 동적 요청을 분리하여 서버 부하를 줄일 수 있다.
- 각각의 서버가 자신의 역할에 집중할 수 있어 성능과 확장성이 향상된다.
- 로드 밸런싱을 통해 대량의 트래픽을 효율적으로 처리할 수 있다.
- Web Server와 WAS를 분리하여 안정적인 서버 운영이 가능하다.

---

### 한계점

- Web Server와 WAS를 별도로 구성해야 하기 때문에 시스템 구조가 복잡해질 수 있다.
- 서버 관리 및 유지보수 비용이 증가할 수 있다.
